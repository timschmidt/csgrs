PURPOSE AND HOW TO USE
This is the deduplicated remaining queue from the whole research effort, not a concatenation of old reports and not an instruction to implement every speculative idea blindly. It is self-contained: the original reports are not required. Recheck the target checkout and repository admission instructions; close a project if newer code already solves it. Select one coherent increment, reproduce its motivating case, establish its mathematical contract, then implement and measure. Preserve exact successful paths before deleting an older adapter. Research leads without a demonstrated defect are labeled accordingly.

PRIORITIES
Exactness > completeness/operation success > performance > low memory > binary size > source size. Improve abstractions/API simplicity where they support these goals. Hypercurve has special priority because it is the most complex codebase. The goal is ordinary CAD workflows without artificial limitations, especially exact representability and computability after repeated operations, not just isolated construction success.

EVIDENCE LIMITS
This effort inspected code and primary mathematical sources. It did not build/run the Rust repository or independently reproduce its benchmark claims. Small independent symbolic/algebraic and ear-clipping model checks were performed, but are not production regressions. Source-derived counterexamples/call counts below are explicitly not runtime measurements. Current source links are pinned; older links identify the inspected implementation seam, not a claim that every line number still matches current HEAD. Rebase anchors before editing.

MATHEMATICAL GUARDRAILS
- Rational polyhedral affine/Boolean operations stay rational. Fixed algebraic-field linear constructions stay in that field. Coefficient bit height can still grow arbitrarily even when topology/field degree stay small.
- New nonlinear roots and independent fields can genuinely enlarge algebraic degree. Preserve selected roots, relations, branch/domain and correlation rather than repeatedly flattening into independent Cartesian expressions.
- General rational spline offsets need not be rational splines. Retained algebraic/procedural carriers are legitimate exact results; a fitted spline or display mesh is not an exact replacement.
- General computable-real zero/equality is not universally decidable. Refinement alone proves separated nonzero values, not arbitrary exact zero. Publish honest admitted-family and resource contracts.
- Keep invalid, unsupported capability, undecided, budget/cancel, empty and unbounded distinct. Structural equality is a positive shortcut; structural inequality is not mathematical inequality.
- Optional optimizations may decline. Honor each API's declared cancellation precedence, including existing cached-proof-before-abort semantics where specified. Hard enclosing budget exhaustion cannot be reset or hidden by cold fallback or a cached proof. Never reset/refund actual work. Existing work units do not cover all scalar arithmetic, precision, time or bytes.
- Preserve inherited fidelity separately from local operation certainty. Keep regularized filled topology separate from open incidence and manifold conversion.

M01 — Bound optional output-coordinate sharing
Status: Highest immediate implementation target; source-derived resource issue

At e2def0b coordinate sharing is exactness-safe in the inspected path, but candidate search is not bounded. Both a structural scan and find(strictly_equal) can scan all active groups. Fixture: x_i=i/2^60, i=0..n-1, n<=2^20, plus a distant x=sqrt(2) sentinel; use rational y,z. The sentinel disables the axis-wide all-rational fast path. The dyadics occupy one approximate window and are all distinct, giving n(n-1)/2 strict comparison attempts: 8,386,560 at n=4096. This is a source-derived count, not executed performance evidence.
Plan: make sharing a bounded best-effort pass. Cap structural candidate inspections AND strict attempts locally and across the pass; bound scratch. Use deterministic shortlists/flat indexed scratch rather than two small vectors per singleton group. Move order reservation after detecting a nonrational axis so all-rational output allocates no sharing scratch. Optional cap/allocation decline may keep exact original coordinates or already-completed certified substitutions. Preserve declared artifact determinism. Current reservation happens before the rational skip and its error propagates through the mandatory call.
Thread operation-level cancellation through collection, comparisons, ranking and final publication. Long sort/scalar calls need their own cooperation. Distinguish an optional sharing allowance from cancellation/hard parent exhaustion: the latter must propagate. Never reset or refund speculative work. The 4096-node ranking cap is per expression, not a pass work/byte bound; f64 candidate conversion can itself refine to precision -1075.
Acceptance: bounded counters on dense unequal/undecided inputs, zero sharing allocations on rational output, exact output on optional decline, typed cancel/exhaustion, existing equal/smallest-expression tests, and subsequent strict operations. Reducing expression size is not by itself proof of easier later predicates.

Status: Validation project; no confirmed geometric regression

M05 — Evaluate fixed-field normalization behind Real
Status: Research prototype; rebaseline after new mesh fixes

Objective: separate unavoidable coefficient growth from avoidable arithmetic-history growth. Linear/affine polyhedral constructions over a fixed algebraic field require no new extension, although coefficient heights can grow.
First measure existing compact_quadratic_tower at a publication or retained-intersection boundary; current 30/45-degree graph-growth motivation has partly been addressed by retained planes and sharing. Proceed only on remaining traces. Do not characterize this compactor as handling the degree-six 10-degree field.
Next prototype an embedded field descriptor (proved irreducible polynomial, selected real embedding, conversion maps) plus reduced coefficient-vector values behind Real/Computable, not a public mesh-only numeric hierarchy. Share descriptor; reduce arithmetic modulo the polynomial; exact zero precedes sign refinement; rational constants promote back to rational. For 30*k use Q(sqrt3); 45*k Q(sqrt2); mixed use degree 4. For 10*k use c=cos(pi/18), m=64c^6-96c^4+36c^2-3, selected c in (49/50,99/100), and sin10=-8c^4+10c^2-2. Sin10's cubic field alone does not contain cos10. Admit rational-turn provenance at construction, not guessed numerical relations.
Acceptance: all rotation multiples, conjugates, dependent generators, reducible-annihilator rejection/local handling, negative plane scales, equal independent descriptors via embeddings, unknown fields retaining fallback, cold archive and drop. Compare publication-only vs construction-boundary vs direct same-field arithmetic. A normalized cache does not release old DAG owners automatically. Fixed degree bounds coefficient count, not bit size, runtime or all nonlinear CAD operations. Do not introduce hyperreal->hypersolve reverse dependencies.

H04 — Own point incidence below topology and reuse concurrency proofs
Status: Hypercurve abstraction and real-CAD completion target

Create an internal point-incidence service over correlated point authorities plus certified support/chart memberships. Move the least-cost equality/order cascade out of competing region/endpoint adapters without deleting specialized kernels. Topology supplies evidence; it should not reconstruct independent coordinates to prove connectivity.
Positive shared definition can prove equality; failed pointer/structural equality proves nothing. Distinct parameters prove distinct points only with injectivity. 9. The old proposed polynomial y^5+y-1 factors into quadratic*cubic. Use H05's y^5+5y+5-x, with Eisenstein at 5, for genuine degree-five continuation.
10. Square-free degree 214 is not proof of minimal/intrinsic degree 214. Conversely a selected-fiber representation does not magically lower an actually degree 214 value's intrinsic degree.
11. A smaller triangle count, normalized graph depth, cached form, or successful display is not proof of lower total cost, lower retained heap, semantic closure or later strict computability.

COMMON ACCEPTANCE MATRIX

For every geometry/authority change include, as applicable:
- empty-result feedback; unchanged operations; proper/tangent/coincident contacts; slivers and near-but-distinct inputs; overlapping components; poles/denominator boundaries; noninjective/retracing maps; endpoints and multiple roots;
- operand swaps, traversal reversal, equivalent equations, source-order permutations, admissible affine/similarity covariance, shared clone versus independent rebuild;
- construct -> restrict/split -> reverse/transform -> Boolean -> offset/fillet or BRep consumer -> archive -> repeat, including generations 1,2,4,8 when geometrically meaningful;
- source/selected-root identity, sheet/domain/inclusion, correlated point replay, inherited fidelity and consumed certainty; input/context drop before output queries;
- strict/approximate/strict, cold/warm/evicted caches, budget boundaries, nested caps, cancellation and retry with more resources; failure must not poison reusable exact capabilities;
- exact independent oracle where feasible, not merely a second wrapper around the same new kernel; explicit row/checksum migration when equal values produce changed artifacts;
- per-case latency/allocation/peak/retained/binary measurements and adverse controls. No source-size win can justify deleting an exact fallback.
