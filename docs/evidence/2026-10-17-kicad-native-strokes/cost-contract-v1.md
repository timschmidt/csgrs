# Source fidelity and resource observations

This is a completeness/source-fidelity migration, not a performance-only
optimization. A baseline rectangular track and the intended round stroke do
not complete the same mathematical contract. Record unsupported/error outcomes
and independently detected incorrect geometry separately; do not report a
faster error or rectangle as a successful round-stroke speedup.

After source/aggregation acceptance and the unchanged workload gates pass,
measure fresh-process and repeated-after-owner-drop source loads. Include
canonical empty and coincident disks (unchanged sets), axial and diagonal
strokes, decimal translation, subrange widths and superrange coordinates.
Compare analytic area/bounds and exact integer point-to-segment membership,
and retain exact scalar/native-boundary snapshots and all disagreements.
Existing native stroke tests establish kernel behavior; this probe must
exercise the public source loader and board aggregation, not bypass either.

Retain all raw latency, allocation-request, peak/retained-request, process RSS,
output-size and binary-size observations. Time complete load, aggregation,
required native queries and snapshot Value materialization. File construction,
process startup, final JSON encoding/file IO and final owner destruction are
outside that interval and must be disclosed. Each sample uses unchanged full
source text. Never remove unfavorable rows. Retained scalar JSON can measure
serialized expression depth and coefficient size, not unique DAG nodes, peak
intermediates, allocator fragmentation or internal heap bounds.

Use alternating baseline/candidate process order with at least three pairs.
Both compiled implementations and all dependency artifacts are read-only and
hash verified before/after. Each subprocess has an external 1800-second and
8-GiB address-space limit. No internal total-work, heap or cancellation bound
is thereby established. Do not run cost samples concurrently with compilation
or another validation workload. Complete project reports require the original
archives, including sidecars, and are separate from standalone board loads.

Any geometry/report/artifact migration must be explained independently of
timing. The 120-second full-board worker CPU and 60-second copper-neck body
wall gates remain binding, with all original fixtures and assertions intact.
