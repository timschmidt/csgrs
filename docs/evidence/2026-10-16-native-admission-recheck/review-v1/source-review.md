# Review of the unchanged pending native change

This is a source-level review, not implementation admission. The 35 paths are pinned in `../pending-source-pins-v1.json`. No source or test changes were made during the original-gates reproduction.

## Construction and evidence ownership

Hypercurve's single-line stroke shortcut follows connectivity, positive-width and corner-style validation, requires a distinct-endpoint certificate, and admits only butt or round caps. Opposite translated parallels and antipodal caps form the exact simple boundary. Unresolved endpoint identity and square caps retain the general path. Hyperdrc lifts finite dyadics before arithmetic and parses KiCad decimal tokens before native construction. The finite report ring is separately documented and can collapse without replacing the authoritative region.

Retained line displacement follows translation and reversal. Restricted fragments use their own endpoint displacement for parameterization while keeping the source support direction. Arbitrary maps discard offset/displacement evidence. Degree-elevated line recovery requires the exact midpoint parameter chart; its producers use affine transformation, de Casteljau subdivision, or equal-valued endpoint replacement. A merely collinear non-affine quadratic remains a quadratic.

Circular support alone does not establish traversal orientation or a single-arc integral. The endpoint tangent path checks a positive radius, a finite endpoint and the homogeneous derivative orientation. The regular-circle shortcut requires an injective quadratic chart; stationary, collapsed and retracing higher-degree controls retain their existing proof paths. The line/circle crossing shortcut uses ordered quadratic roots and a separately recovered strict arc orientation.

## Winding and caches

The interval filters use certified enclosures, decide only separated bounds, and retain the original predicates for overlap or absent evidence. Contour bounds are shared only by immutable contours; explicit work-budget and preview/speculative paths avoid the persistent winding cache. An uncertain warm query retries fresh bounds. Native contour winding reuse preserves the material/hole traversal bins and keeps origin-contact handling on the source loop.

The circular relation index keeps exact rational keys and preserves the original first-match order against symbolic entries. Authored continuation precomputation preserves incident order and overlap ownership. Opposite-side winding inference requires a single noncoincident boundary and an interior representative. Lazy ray construction exhausts the same strict witnesses before the terminal approximate pass.

## Observable migration and failure

KiCad straight tracks gain exact round caps, including a disk at coincident endpoints; zero width is empty. Malformed tracks remain failed features instead of disappearing. The check implementation version changes from 20 to 21. The documented finite `line_polygon` rejection contract remains `None`; admitted construction failure stays on its returned owner. Checked polygon handoff, area, bounds and profile aggregation inspect retained construction failures and the shared budget before publishing success.

Existing independent tests include analytic capsule areas and bounds, integer sector membership, nested-loop winding vectors, exact dyadic extremes, exact decimal source values, higher-degree circle counterexamples, exhaustion and recovery. Wrapper agreement is additional evidence only. These tests still need execution on the current final source.

## Remaining admission work

The runtime gates alone do not prove geometry semantics, complete report equality, all cache states or a resource bound. Current native tests, lint and docs still need qualification. Previously measured cost regressions concerned distinct scalar/allocator combinations; they must not be attributed to one pending component without a controlled comparison. The persistent native caches and construction fast paths need proportional current cost evidence before performance claims. Full internal work/heap bounds, typed failure-category refinement, end-to-end qualification through lossy formats, and clean packaged release validation remain broader open work.
