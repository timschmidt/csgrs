# Construction cache-event coverage

The two scalar construction windows with earlier large timing regressions
execute **zero instrumented cache/normalizer events**. This diagnostic does
not select a runtime change or admit either rejected native combination.
The complete properties plan remains open.

The [reviewed source snapshot](source-review-v1.json) adds counters to five
paths in a separate copy of the full-cache candidate. Algorithms, budgets,
cache payloads, arithmetic order and ownership are preserved. The standalone
probe retains the original fixture, expected-answer and witness code exactly.

The [assessment](assessment-v1.json) verifies formatting, all-feature
all-target Clippy with warnings denied, and **875 scalar unit tests**: the
prior 868, six existing cache controls and one new counter sanity control.
The latter observes cold publication followed by exact zero-work replay.
These are scalar and diagnostic checks, not complete stack qualification.

Two fixed fresh processes yield 64 rows with 27 event counters each. Counts
repeat exactly, satisfy conservation checks, and preserve every prior public
arithmetic count, exact witness and representation inventory.

Every construction phase has zero retained hits, publications and evaluation
cache allocations. Across construction and query phases together, one process
records 48,568 retained hits and 36,279 publications. Full rows are retained
in [samples.json](diagnostic-v1/samples.json).

The [decision](decision-v1.json) leaves elapsed-cost attribution open. Cache
copy removal has no observed direct work to remove in the two expensive
construction windows. Earlier-phase state, code generation and environment
remain unproven explanations. Instrumented durations are not cost evidence;
the byte counters cover specified Box requests, not total live memory or RSS.

A [read-only capability check](performance-counter-capabilities-v1.json)
found user cycle/instruction counters available and reference cycles
unsupported. CPU 0 currently uses the powersave governor; this does not
establish its state during prior measurements. The [next diagnostic
review](next-diagnostic-v1.json) concerns per-phase hardware counts using
unchanged libraries and a separate observation wrapper. It is not prepared.
