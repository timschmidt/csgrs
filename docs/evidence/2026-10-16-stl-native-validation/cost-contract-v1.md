# Complete STL import and consumption cost

Freeze `import_cost_v1.rs` before compilation. Compare the retained minimal-feature libraries for current commit 7a1f0c7e1 and the isolated native-validation candidate, using the same Rust compiler, optimized flags, instrumented System allocator and inputs. Candidate validation must finish before timing begins. Read completed targets without modifying them.

Run five alternating baseline/candidate pairs for each of six workloads: binary and ASCII encoding of canonical empty, one unit cube, and 256 disconnected unit cubes at x = 3i. Each workload runs in a fresh process. The independently generated coordinates are exactly representable binary32 values; normals are unused zero records. Preserve every sample, input and complete materialized position/index output.

Measure a first call followed by 64 repeated calls for empty/unit or four calls for the large fixture. Every call parses the complete input into a new native mesh, performs strict closed-PWN validation for nonempty output, and consumes it through union with canonical empty. Retain every resulting mesh until measurement ends. Input construction, outer retention-vector allocation, semantic checks and writing comparison files are outside timing; native result materialization, proof retention and the subsequent union are inside. Separate import duration from the complete pipeline duration. Repeated calls have fresh geometry identities but may benefit from process-global scalar state; this is not a general cold-cache campaign.

Outside timing, compare each oriented face against independently specified exact coordinates, manifoldness and the exact winding integral 6N. Compare complete output position/index bytes between every retained result and both variants. For the empty case the modeling empty-set bridge applies; native nonempty-PWN validation does not. These checks supplement, rather than replace, the scale, malformed-topology and repeated-composition acceptance matrix.

The System allocator wrapper reports successful allocation/reallocation calls, requested bytes, additional peak live requested bytes and retained requested-byte delta during each phase. Reallocation counts the whole new request; these are Rust global allocator observations, not allocator metadata, native-library heap use, OS heap bytes or a public memory bound. Instrumentation and timing calls affect both executables; no uninstrumented latency claim follows. GNU time reports process peak RSS. Keep binary sizes, hardware, toolchain, library hashes, flags, policies and raw output. Use 120-second elapsed and 8-GiB address-space external limits for each process.

This is a focused correctness-change cost comparison, not an optimization admission or a statistical performance claim. Faster invalid-input rejection is not measured as completed modeling. Report all slowdowns as well as improvements. The full application workload, all topology families, parser allocation bounds and cancellation remain outside this cost probe.
