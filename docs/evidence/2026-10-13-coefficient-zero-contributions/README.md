This diagnostic measures how often the original coefficient multiplier executes
a linear radical or opaque-atom product with a stored zero rational scale.
It starts from the unchanged endpoint candidate; both rejected scaling variants
remain excluded. No runtime optimization is admitted.

The fixed counters record 64 shape/zero bins after the original unsupported
product guard and actual entries at each of the four linear contribution loops.
An early insertion failure can prevent later entries, so input lengths are not
used as substitutes for executed products. Zero flags read `Rational::is_zero`,
which checks the stored sign without canonicalization or refinement. Every
original arithmetic operation, insertion, early return and cache pass remains.

Before the one complete-board observation, four calibration/site tests, six
cache-frontier tests, five endpoint tests, formatting and strict release,
all-feature, all-target Clippy must pass. The original fixtures and 120-second
worker-CPU assertion remain intact. Counters print after that assertion,
including during unwinding. Source, executable, input and main-worktree hashes
bind the resulting evidence to this isolated diagnostic.

The preregistered coverage screen is at least 100,000 executed zero products
and at least 5% of executed linear entries. Passing it warrants investigation
of a separate runtime candidate; it does not predict saved time or allocations.
Rational multiplication already returns early on zero. Any candidate still
needs correctness, fixed scalar/native costs, both original native gates and
complete report identity before retention.

Preparation is recorded before execution. Results will be recorded separately;
the endpoint parent's unresolved tradeoffs and all 35 pending native entries
remain in scope.
