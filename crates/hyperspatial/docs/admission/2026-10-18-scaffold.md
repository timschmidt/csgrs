`dbe99e3cc145e8ca58a53ade6e79fd46311972fb`.

## Contract and ownership

The owning boundary is workspace/package integration under P37, with the
P35–P39 evidence and scope requirements. The input domain is Cargo package
discovery, an empty Rust library, and repository documentation. There are no
geometric or astronomical inputs, outputs, predicates, caches or numerical
resource contracts to validate in this change.

Before adding the crate, `cargo metadata --offline --no-deps --format-version 1`
reported 19 workspace members and no `hyperspatial` package. That missing
package was the scaffold's acceptance gap. The existing root membership rule,
`members = ["crates/*"]`, is sufficient to discover the new crate.

The [development plan](../../DEVELOPMENT.md) assigns future numerical ownership,
domains and missing acceptance cases. The
[astronomy plan](../astronomy.md) extends those cases to time, frames, states,
observers, kernels and observations. These inventories are requirements, not
evidence that their implementations exist.

## Retained changes and design decisions

- Created the requested local branch and an unpublished `hyperspatial` 0.1.0
  library package, with edition 2024 and declared Rust 1.95.0 minimum.
- Recorded Earth geodesy, projections and local frames as the initial priority.
- Required `hyperreal::Real` or `Real`-backed production numerical quantities,
  including time. External crates are development-only test/benchmark oracles
  and algorithmic inspiration. There are no dependencies in this scaffold.
- Added the [ecosystem/API comparison](../ecosystem.md), primary-source astronomy
  research, native-layer ownership and explicit acceptance stages.
- Added only the package name/version entry to the root lockfile. No existing
  dependency versions, CI configuration or kernel code changed.

The retained artifact is this plan and package structure. External runtime
backends are excluded by the agreed scope. Algorithm selection, numerical
implementation and performance claims remain open. Empty placeholder tests
would not establish numerical behavior and were not added.

## Limits and next admission boundary

The declared 1.95.0 minimum compiler is not validated here; installed toolchains
do not include it. Numerical/model accuracy, platform bindings, WASM,
performance and a released external-consumer workflow remain unimplemented
or unvalidated. There is no published distribution to install.
Planning documents intentionally link to surrounding monorepo sources; their
standalone distribution needs review before a release.

No existing package depends on this crate, so there is no affected downstream
numerical path to retest. The complete repository workflow/pre-push campaign
was not run; no push is part of this change. The
[repository pre-push gate](../../../../AGENTS.md) still applies before a push.

The next implementation must begin with a specific E1 contract and a missing
acceptance fixture, add only the native dependencies it consumes, and retain
evidence through the actual public transformation path. A green scaffold build
does not discharge that requirement.
