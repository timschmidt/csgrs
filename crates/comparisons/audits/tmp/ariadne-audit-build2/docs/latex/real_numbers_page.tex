For information on logic for real number computation, see the \doxysectlink{logic_page}{Logical Foundations}{0}.\hypertarget{real_numbers_page_algebraicnumbers}{}\doxysubsection{\texorpdfstring{Algebraic Numbers}{Algebraic Numbers}}\label{real_numbers_page_algebraicnumbers}
The algebraic numbers $\mathbb{A}$ are those which are the solution of polynomial equations with integer (equivalently, rational) coefficients. They characterised by exact arithmetical operations and decidable comparisons. Well known sub-\/classes of algebraic numbers are the integers $\mathbb{Z}$ and the rationals $\mathbb{Q}$. The dyadic (rational) numbers $\mathbb{Q}_2$ have the form $p/2^q$ for integers p, q, and are important in computation, since they can be expressed exactly as binary expansions. Further, they are the "{}simplest"{} dense set of algebraic numbers closed under addition, subtraction and multiplication. The dyadic numbers do not in general support exact division. The exception is that division by a power of $2$ yields an exact answer.

Elements of a countable set of numbers, such as integer, dyadic, rational or algebraic numbers, may be stored using a finite amount of data, though the size of the data depends on the element used. Hence in an array of an exact arithmetic type, each element needs to be dynamically allocated, which is expensive in terms of spacial overhead. Since these sets are typically closed under arithmetical operations, arithmetic can be performed exactly for these types. Hence these types are appropriate where time and space overhead are not at a premium.

Since these types require arbitrarily large amounts of memory which is typically dynamically allocated, and hardware support for arithmetic does not exist, they are typically less efficient than the fixed-\/precision and multiple-\/precision types, described later.\hypertarget{real_numbers_page_realnumbers}{}\doxysubsection{\texorpdfstring{Real Numbers}{Real Numbers}}\label{real_numbers_page_realnumbers}
Classically, real numbers are either defined axiomatically, or constructed using Dedekind cuts or Cauchy sequences.

A Dedekind cut is a pair of sets $(L,U)$ such that
\begin{DoxyItemize}
\item $L,U \subset \mathbb{Q}$ and $L \cap U = \emptyset$
\item $ l\in L \implies \forall l\textnormal{\textquotesingle}<l,\ l\textnormal{\textquotesingle} \in L $ and $ u \in U \implies \forall u\textnormal{\textquotesingle}>u,\ u\textnormal{\textquotesingle} \in U $
\item $ \forall l \in L, \exists l\textnormal{\textquotesingle} \in L,\ l\textnormal{\textquotesingle}>l $ and $ \forall u \in U,\ \exists u\textnormal{\textquotesingle}\in U, u\textnormal{\textquotesingle}<u $
\item $ l < u \implies l\in L \vee u \in U $
\end{DoxyItemize}

A sequence $(q_n)$ of (dyadic) rationals is a Cauchy sequence if
\begin{DoxyItemize}
\item $ \forall \epsilon>0,\ \exists N\in\mathbb{N},\ \forall m,n>N,\ d(q_m,q_n)<\epsilon$.
\end{DoxyItemize}

Two Cauchy sequences $(p_n)$, $(q_n)$ are equivalent if
\begin{DoxyItemize}
\item $ \forall \epsilon>0,\ \exists N\in\mathbb{N},\ \forall n>N,\ d(p_n,q_n)<\epsilon$.
\end{DoxyItemize}

In both the above definitions, it is possible to use dyadics instead of rationals.

Unfortunately, without knowledge of the convergence rate, no information about the limit can be obtained from an initial part of a Cauchy sequence. For this reason, real numbers defined as Cauchy sequences of (dyadic) rationals are known as "{}\+Naive"{} reals, which we shall denote $\mathbb{R}_?$.

Instead, the computable or effective real numbers $\mathbb{R}$ are defined as (equivalence classes of) fast converging Cauchy sequences, which satisfy
\begin{DoxyItemize}
\item $ \forall m,n \in \mathbb{N},\ d(q_m,q_n)<2^{-\max(m,n)}$.
\end{DoxyItemize}

There are many equivalent representations of computable real numbers. An alternative is that of {\itshape nested intervals} $[\underline{q}_n\!:\!\overline{q}_n]$ such that
\begin{DoxyItemize}
\item $\underline{q}_n \leq \underline{q}_{n+1} \leq \overline{q}_{n+1} \leq \overline{q}_n$ and
\item $\bigcap_{n\in\mathbb{N}}[\underline{q}_n\!:\!\overline{q}_n]=\{q\}$.
\end{DoxyItemize}

Alternatively, we may consider {\itshape strictly nested} intervals
\begin{DoxyItemize}
\item $\underline{q}_n < \underline{q}_{n+1} < \overline{q}_{n+1} < \overline{q}_n$. These representations are essentially equivalent to the Dedekind reals.
\end{DoxyItemize}

The computable reals support the standard arithmetical operations and elementary functions. Further, one can compute bounds to any given accuracy. However, comparisons are undecidable, since given two computable reals which happen to be equal, equality cannot be proved by finite-\/precision approximations, no matter how accurate. For this reason, comparison returns an object of the Kleenean logical type $\mathbb{K}$.

\doxylink{namespaceAriadne_adeaa7a0ec0b9b19cd7a7d32ac6aa4111}{Weaker} information is given by the {\itshape lower reals} $\mathbb{R}_<$, defined by bounded increasing sequences of (dyadic) rationals $(\underline{q}_n)$, which satisfy
\begin{DoxyItemize}
\item $\underline{q}_n \leq \underline{q}_{n+1}$ and
\item $ q = \lim_{n\to\infty} \underline{q}_n = \sup_{n\in\mathbb{N}}\underline{q}_n$
\end{DoxyItemize}

and the {\itshape upper reals} $\mathbb{R}_>$, defined by bounded decreasing sequences of (dyadic) rationals $(\overline{q}_n)$, which satisfy
\begin{DoxyItemize}
\item $ \overline{q}_n \leq \overline{q}_{n+1}$ and
\item $ q = \lim_{n\to\infty} \overline{q}_n = \inf_{n\in\mathbb{N}}\overline{q}_n $.
\end{DoxyItemize}

Note that negation reverses lower and upper real types, and multiplication is not supported, since e.\+g. given approximations $q_1 > r_1$ and $q_2 > r_2$, one cannot deduce $q_1 \times q_2 \geq r_1 \times r_2$. For we have $2>-3$ and $3>-5$, but $ 6 = 2\times 3 \not\geq 15 = (-3)\times(-5)$. However, multiplication and division of {\itshape positive} lower/upper reals is possible e.\+g. $\R^+_> \div \R^+_< : \R^+_>$. Also, upper/lower reals can be multiplied by positive reals e.\+g. $\R_> \times \R^+ : \R_>$.

The full overloads for multiplication are \[ \R_>\!\times\R^+,\;\R^+\!\times\R_>:\R_>; \quad \R\times\R:\R; \qquad \R^+_>\times\R^+_>:\R^+_>; \quad \R^+\!\times\R^+:\R^+ . \] Note that the dispatch for $\R\times\R^+$ (and for $\R^+\!\times\R$) is ambiguous, but that $\R\times\R:\R$ is better than $\R_>\times\R^+:\R_>$.

An implementation of the computable real number type may store a number in a form so that it can be recovered to any desired precision. This is typically acheived by expressing the number as a formula in terms of other arbitrary-\/precision or exact number types. However, the high computational overhead of such numbers makes them impractical for describing higher-\/order types, such as matrices or sets.

When specifying a real number by a symbolic formula, such as {\ttfamily x = exp(2/3)}, there may be many ways of computing the operations used in the definition. Currently, Ariadne uses a default calculus of elementary functions (based on the MPFR package), and any real number defined in terms of such functions can be computed directly. However, if we wish to use an alternative implementation of the elementary functions, or compute with more complicated operations, we need to use an evaluator class to perform the required calculus.\hypertarget{real_numbers_page_floatingpointarithmetic}{}\doxysubsection{\texorpdfstring{Floating-\/\+Point Arithmetic}{Floating-\/\+Point Arithmetic}}\label{real_numbers_page_floatingpointarithmetic}
In numerical analysis, real numbers are traditionally described by floating-\/point types float and double. The set of elements which can be represented by these types is finite. Arithmetic operations can only be performed approximately to maximal precision determined by the data type. However, these types have the advantage of requiring a known amount of memory, which means they can be statically allocated, and having hardware-\/supported arithmetical approximations. This makes them especially suitable in situations where execution speed and memory usage are more important than a knowledge of the computational accuracy.

If we have a problem for which a fixed-\/precision type is not sufficient to obtain an accurate answer, we can switch to a multiple-\/precision type. The semantics of arithmetic on multiple-\/precision types is mostly the same as that of a fixed-\/precision type; arithmetic is approximate, and the default is to return an interval. However, a multiple-\/precision type can use arbitrarily high precison; in particular, the set of all such numbers is the dyadic numbers. However, the precision provides a grading of the type into sets $\mathbb{F}_p$ with $\mathbb{F}_{p_1} \subset \mathbb{F}_{p_2}$ for $p_1\leq p_2$, and $\bigcup_{p\in\mathbb{N}}\mathbb{F}_p = \mathbb{Q}_2$. Using a higher precision yields a more accurate answer. Further, the result of an arithmetic operation is guarenteed to converge as the precision is increased. For efficiency, all elements of an array of a multiple precision type

An arbitrary precision floating-\/point type is a template class whose precision is a template parameter. Such a class can be implemented using a multiple-\/precision type, but has the advantage that it does not need to dynamically-\/allocate memory.

For a package such as Ariadne, in which we are concerned with keeping track of numerical errors, it is dangerous to use a {\ttfamily Float} type directly. However, in low-\/level code it is appropriate to use these types. Instead, we provide four different arithmetic operations for the same type. We can specify that the result can be rounded {\itshape up} or {\itshape down}, or that the result should be rounded to the {\itshape nearest} representable value. Algebraic and transcendental functions are provided with both rounded and interval versions. For example, multiplication with upward rounding is defined by add(up,x,y).

Currently, Ariadne supports the double-\/precision floating-\/point type, and a multiple-\/precision type based on the MPFR package. Currently, there are no arbitrary-\/precision floating-\/point types.

Alternatives to using rounded builtin floating-\/point arithmetic exists, which may be more effiucient on some processors. Since keeping track of rounding is tedious and error-\/prone, rigorous arithmetic using floating-\/point numbers is typically performed using interval arithmetic. Here, computation of a real number $x$ yields an interval $[\underline{x}\!:\!\overline{x}]$ such that $ \underline{x} \leq x \leq \overline{x}$. Arithmetical operations $\star$ are defined to preserve inclusion, so that e.\+g. $ x\in [\underline{x}\!:\!\overline{x}] \wedge y\in [\underline{y}\!:\!\overline{y}] \implies x \star y \in [\underline{x}\!:\!\overline{x}] \star [\underline{y}\!:\!\overline{y}] $. Interval arithmetic can be implemented in terms of rounded arithmetic. e.\+g. $[\underline{x}\!:\!\overline{x}] - [\underline{y}\!:\!\overline{y}]=[\underline{x}-_\downarrow \overline{y}:\overline{x}-^\uparrow\!\underline{y}]$.

In Ariadne, we use a {\ttfamily \doxylink{classAriadne_1_1Bounds}{Bounds$<$\+F$>$}} class rather than {\ttfamily \doxylink{classAriadne_1_1Interval}{Interval$<$\+F$>$}} for interval arithmetic, since Interval is reserved for geometric intervals (sets), rather than information about points.

Finite precision interval operations satisfy the mathematical postcondition $ \forall x\in [\underline{x}\!:\!\overline{x}],\ f(x)\in f([\underline{x}\!:\!\overline{x}])$. Multiple-\/precision interval functions follow the same conditions as fixed-\/precision interval functions, together with the convergence criterion that the length of $f([\underline{x}\!:\!\overline{x}])$ approaches $0$ as the width of $[\underline{x}\!:\!\overline{x}]$ approaches $0$. In particular, if $[\underline{x}\!:\!\overline{x}]$ is a sequence of intervals with nonempty interior whose radius approaches $0$, then the radius of $f([\underline{x}\!:\!\overline{x}])$ approaches $0$.
