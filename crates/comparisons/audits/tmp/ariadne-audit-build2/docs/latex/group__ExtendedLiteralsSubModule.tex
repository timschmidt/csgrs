Indicate that a floating-\/point literal is the exact value of a number in double-\/precision. 

The input {\itshape lx} is converted first converted to a double-\/precision value {\itshape x}. If {\itshape lx} and {\itshape x} differ, then the decimal literal input to {\itshape lx} almost certainly does not represent a double-\/precision number exactly, and an assertion fails. 

For example, {\ttfamily 0.\+625\+\_\+x} yields the exact double-\/precision value $5/2^3$, but {\ttfamily 0.\+6\+\_\+x} fails, since $3/5$ is not exactly representable as a double-\/precision number. \Hypertarget{group__ExtendedLiteralsSubModule_gabd313746e70a0e828a8a9d12483ada8d}\index{Extended numeric literals@{Extended numeric literals}!operator"{}"{}\_pr@{operator""""\_pr}}

Indicate that a floating-\/point literal is sufficiently precise that it can safely be taken to represent the closest double-\/precision floating-\/point number. 

For example, writing {\ttfamily 0.\+14285714285714285\+\_\+pr} claims that the exact decimal "{}0.\+14285714285714285"{} should be interpreted as the closest double-\/precision floating-\/point number, which has exact value $0.142857142857142849212692681248881854116916656494140625$.
