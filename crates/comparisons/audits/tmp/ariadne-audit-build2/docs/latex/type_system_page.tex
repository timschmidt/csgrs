\hypertarget{type_system_page_overview_computability}{}\doxysubsection{\texorpdfstring{Representations}{Representations}}\label{type_system_page_overview_computability}
Objects from discrete mathematics, such as integers and rational numbers, can be described by a finite amount of data. (This holds even if the sets themselves are infinite, though we then need an arbitrarily large amount of data to store objects.) We can think of this data as a {\itshape word} over some {\itshape alphabet} $\Sigma$. A {\itshape naming system} for a finite set $X$ is a partial surjective function $\nu:\Sigma^*\to X$ taking concrete data to the mathematical entity it describes. Hence every object in $X$ has at least one description or {\itshape name}, but this need not be unique, and not all words are valid names
\begin{DoxyItemize}
\item e.\+g. $\nu(\texttt{2/3})=\nu(\texttt{4/6})=\frac{2}{3}$, but $\texttt{2/3/5}$ is not a valid name of a rational number.
\end{DoxyItemize}

Ariadne mainly deals with objects from uncountable sets, such as real numbers and continuous functions. It is impossible to find a description of objects from such sets for which objects are encoded by a finite amount of data. However, all the objects we study have {\itshape continuum cardinality}, and can be encoded by an infinite {\itshape stream} of (binary) data. Then a naming system or {\itshape representation} is a partial surjective function $\mu:\Sigma^\omega \to X$.
\begin{DoxyItemize}
\item e.\+g. $\texttt{3.14159}\cdots$ is an initial segment of the name of $\pi$ in decimal.
\end{DoxyItemize}

It is of course, impossible, to compute the complete name of an object. For this reason, it is important that we can extract useful information about an object from a finite prefix of the name.
\begin{DoxyItemize}
\item e.\+g. Given $\mu(\texttt{3.14159}\cdots)=p$, we know for sure that $p\in[3.14159\!:\!3.14160]$.
\end{DoxyItemize}\hypertarget{type_system_page_effective_validated}{}\doxysubsection{\texorpdfstring{Effective and Validated types}{Effective and Validated types}}\label{type_system_page_effective_validated}
The relationship between infinite and finite data gives rise to one of the core conceptualisations in Ariadne, that of the kind of {\itshape information}. We have already seen \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated} information, which is finite, and provides {\itshape guarantees} about the value of the object, without specifying it completely, and \doxylink{classAriadne_1_1Concepts_1_1Effective}{Effective} information, which is infinite, but from which \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated} information can be extracted. The amount of information which is extracted is given by a parameter \doxylink{classAriadne_1_1Concepts_1_1Effort}{Effort} (this name may change in future). Hence we have a constructor \doxylink{classAriadne_1_1Concepts_1_1Validated_af112ad64c20615a64f94d542891d5e34}{Validated$<$\+T$>$\+::\+Validated(\+Effective$<$\+T$>$,\+Effort)}, or a function \doxylink{namespaceAriadne_1_1Concepts_ab75902ce140ddb1b7f194ef5d25dd259}{compute(Effective\texorpdfstring{$<$}{<}T\texorpdfstring{$>$}{>}, Effort) -\/\texorpdfstring{$>$}{>} Validated\texorpdfstring{$<$}{<}T\texorpdfstring{$>$}{>}} which performs the computation.

For a given type, there are many possible {\itshape equivalent} naming systems. For example, we could describe a real number using a binary or a decimal expansion (though it turns out that these are not {\itshape quite} equivalent, or even appropriate). Hence our \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated\texorpdfstring{$<$}{<}T\texorpdfstring{$>$}{>}} is a {\itshape generic} class which can store a description in {\itshape any} such {\itshape admissible} representation. In order to use the computed information, we must be able to manipulate it in some concrete way. For number classes such as \doxylink{classAriadne_1_1Concepts_1_1Validated_3_01Real_01_4}{Validated\texorpdfstring{$<$}{<}Real\texorpdfstring{$>$}{>}}, this is typically a therefore define for each type of mathematical object {\ttfamily T}, certain concrete classes which can be gotten from a \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated\texorpdfstring{$<$}{<}T\texorpdfstring{$>$}{>}} using a {\itshape getter} method. For function types, this is typically a way of evaluating the function.

The information provided by a finite prefix of a name of an object does not specify the object exactly, but instead merely shows that the object lies in a restricted set of possibilities. For an admissible representation, this set is related to the topology of the represented space. Theoretically, we find a {\itshape basic open subset} containing the object, though for practical reasons, it is usually more convenient to take the closure (in a locally-\/compact Hausdorff space). Since different representations may correspond most naturally to different bases, our \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated} types do not force a particular concrete description, but merely require that suitable information can be extracted e.\+g. \doxylink{namespaceAriadne_1_1Numeric_ae50b9b3abc4cf0f171da2652a2c5b8e1}{Dyadic\+Bounds} for a \doxylink{classAriadne_1_1ValidatedReal}{Validated\+Real} number.

Although \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated} information encodes sets of mathematical values, we do not conceptualised them as sets in Ariadne. For validated information represents partial knowledge about a single value, rather than describing a collections of values. For this reason, we do not provide set-\/theoretic operators such as subset tests and intersections, but predicates refines(\+Validated$<$\+T$>$,\+Validated$<$\+T$>$), inconsistent(\+Validated$<$\+T$>$,\+Validated$<$\+T$>$) and a refinement(\+Validated$<$\+T$>$,\+Validated$<$\+T$>$) operator. Note that the {\ttfamily refines} and {\ttfamily inconsistent} predicates check if they are {\itshape definitely} true, and may return {\ttfamily false} even when satisfied to provide faster checks.

The length of the information describing a \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated} object provides an integer {\itshape grading} of information. We shall later see that it is convenient to sometimes provide more parameters (called {\itshape properties}) of an object controlling how the information is represented. (e.\+g. a polynomial approximation to a function may be controlled both by a {\itshape precision} of its coefficients, and the maximum {\itshape degree} of its terms.) It is also sometimes convenient to {\itshape forget} the length of information stored. (e.\+g. a decimal approximation {\ttfamily 0.\+75000000} to a value may be truncated/simplified to {\ttfamily 0.\+75}.) The choice here affects the ability to estimate the amount of work that should be put in to computing an \doxylink{classAriadne_1_1Concepts_1_1Effective}{Effective} object which is to be combined with a \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated} object.

In some cases, rigorous bounds on a value are not needed, and we can use \doxylink{classAriadne_1_1Concepts_1_1Approximate}{Approximate} computation, which is usually faster. A common use-\/case for approximate computation is to precondition or hotstart a rigorous computation.

When specifying a problem, we may not even wish to specify which representations and algorithms to use, leaving this open for parametrisation. An object which is mathematically well-\/defined, but for which no computational content is specified, is \doxylink{classAriadne_1_1Concepts_1_1Abstract}{Abstract}, and will typically have a \doxylink{classAriadne_1_1Concepts_1_1Symbolic}{Symbolic} description. e.\+g. {\ttfamily 3\texorpdfstring{$\ast$}{*}atan(sqrt(3))} defines a number, but requires concrete algorithms for {\ttfamily sqrt} and {\ttfamily atan} in order to compute.

Type modifiers include \doxylink{classAriadne_1_1Concepts_1_1Lower}{Lower}, \doxylink{classAriadne_1_1Concepts_1_1Upper}{Upper}, \doxylink{classAriadne_1_1Concepts_1_1Naive}{Naive}, \doxylink{classAriadne_1_1Concepts_1_1Positive}{Positive}, \doxylink{namespaceAriadne_1_1Concepts_a6af75924672fc0f6ed1b6e87185dbed3}{Completion\+Type$<$\+T$>$}, \doxylink{namespaceAriadne_1_1Concepts_ab0e219279e6150966915e0c9bc4cd067}{Generic\+Type}

Types associated with an object are given by its \doxylink{classAriadne_1_1Concepts_1_1Traits}{Traits}.\hypertarget{type_system_page_completion_function}{}\doxysubsection{\texorpdfstring{Completion and Function types}{Completion and Function types}}\label{type_system_page_completion_function}
There are two main ways of forming effective types in Ariadne, namely via completions and functions.\hypertarget{type_system_page_completion_types}{}\doxysubsubsection{\texorpdfstring{Completion Types}{Completion Types}}\label{type_system_page_completion_types}
The completion construction can be applied to both metric and ordered types.

In the metric case, the class should provide a dist(...) function giving the metric, or support either taking abs(...) or norm(...), returning a positive upper bound. The metric completion is {\itshape not} the usual completion via Cauchy series, but use {\itshape fast} Cauchy sequences $(q_n)$ satisfying \[ d(q_{n_1},q_{n_2}) \leq 2^{-\min(n_1,n_2)} . \] In this way, if $x_\infty = \lim_{n\to\infty} q_n$, then it is known that \[ d(x_\infty,q_n) \leq 2^{-n} \] or, equivalently, \[ x_\infty \in B_{2^{-n}}(q_n) . \] An alternative to using a fast Cauchy sequence is to give an {\itshape error seqence} $(e_n) \searrow 0$ and require \[ d(q_{n_1},q_{n_2}) \leq e_{\min(n_1,n_2)} . \]

In the ordered case, there are {\itshape directed} completions, {\itshape lower} and {\itshape upper}, which denote the limit of a monotone sequence. \[ q_{n+1} \geq q_n  \text{ or } q_{n+1} \leq q_n \] Combining both kinds of information gives a two-\/sided completion.

If no convergence rate is given, we obtain the {\itshape naive} completion. Although the sequence converges, no information about the limit can be obtained from any finite prefix of the sequence, so the naive completion is essentially useless! However, \doxylink{classAriadne_1_1Concepts_1_1Approximate}{Approximate} information is equivalent to \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated} \doxylink{classAriadne_1_1Concepts_1_1Naive}{Naive} information. For this reason, we one could include the naive completion to round off the type system.

Although these completion constructions can be defined in terms of limits of sequences of {\itshape points}, in Ariadne, we always consider the result as defining a (nested) sequence of {\itshape sets}, each of which contains the correct value. The types of these sets are \doxylink{classAriadne_1_1Ball}{Ball} for metric space completions, \doxylink{classAriadne_1_1Bounds}{Bounds} for ordered completions, \doxylink{classAriadne_1_1LowerBound}{Lower\+Bound} and \doxylink{classAriadne_1_1UpperBound}{Upper\+Bound} for increasing and decreasing completions, and \doxylink{classAriadne_1_1Approximation}{Approximation} for the naive completion. These classes, along with (Exact)Value form the main kinds of concrete information in Ariadne.

When an Algebraic object supports a completion, this is indicated as the \doxylink{namespaceAriadne_1_1Concepts_a6af75924672fc0f6ed1b6e87185dbed3}{Completion\+Type}.\hypertarget{type_system_page_function_types}{}\doxysubsubsection{\texorpdfstring{Function Types}{Function Types}}\label{type_system_page_function_types}
A {\itshape function} type Function is characterised by its {\itshape signature}, which in C++ has the form {\ttfamily R(\+A0,\+A1,...)}, and is specified by its {\itshape evaluation} or {\itshape call} operator, -\/\texorpdfstring{$>$}{>}R or evaluate(\+Function\+Concept$<$\+R(\+AS...)$>$ f, AS...)

When the arguments of the function are completions, there is a {\itshape canonical} conversion (N.\+B. This statement needs to be checked to see if it holds in full generality) from \doxylink{classAriadne_1_1Concepts_1_1Effective}{Effective} to \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated}. For evaluating the function on an effective object requires computing information on the result from a finite amount of information on the argument. This means that an effective function maps \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated} objects to \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated} objects, so can also be seen as a \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated} function.

Note that while both an {\ttfamily \doxylink{group__FunctionModule_ga1ce9d5a1cfb352fbd1daf2f696740357}{Effective\+Function$<$\+R(\+A)$>$}} and a {\ttfamily \doxylink{group__FunctionModule_gad8dd512fc373fa20822aefa98e73ab5a}{Validated\+Function$<$\+R(\+A)$>$}} are functions from {\ttfamily \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated}}  to {\ttfamily \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated$<$\+R$>$}}, they also satisfy additional constraints on the image. A validated function $\hat{f}$ should be {\itshape monotone} in the arguments i.\+e. $\hat{x} \subset \hat{y} \Rightarrow \hat{f}(\hat{x})\subset\hat{f}(\hat{y})$, and an effective function $f$ must also be {\itshape convergent} i.\+e. $\bigcap_{n=0}^{\infty}\hat{x}_n=\{x\} \Rightarrow \bigcap_{n=0}^{\infty} f(\hat{x}_n) = \{f(x)\}$

Ariadne also supports function classes with more information. Most \doxylink{classAriadne_1_1Function}{(Continuous)Function} objects can be evaluated on appropriate algebras, and Differentiable\+Function objects support differentiation. Further, Piecewise\+Continuous\+Function support restricted evaluation, and Measurable\+Function objects are defined in terms of (pre)images of sets, and do not support evaluation at all.

REMARK\+: We are in the process of refactoring the function classes, so the information gives details of future behaviour.\hypertarget{type_system_page_cartesian_closed}{}\doxysubsubsection{\texorpdfstring{Product, union and sub-\/types}{Product, union and sub-\/types}}\label{type_system_page_cartesian_closed}
In addition to completion and function types, we can also define types as (cartesian) {\itshape products}, as disjoint {\itshape unions}, or as {\itshape subtypes}. In principle, this makes Ariadne\textquotesingle{}s type system a {\itshape Cartesian closed category}, though in practice we do not support arbitrary higher-\/order types.\hypertarget{type_system_page_concrete_generic_algebraic}{}\doxysubsection{\texorpdfstring{Concrete, Generic and Algebraic types}{Concrete, Generic and Algebraic types}}\label{type_system_page_concrete_generic_algebraic}
Computations in Ariadne are performed by classes which support efficient operations for the problem at hand. Each of these classes is a concrete model for a mathematical abstraction, such as a number, function, or set. The relationship between these \doxylink{classAriadne_1_1Concepts_1_1ConcreteConcept}{Concrete} and \doxylink{classAriadne_1_1Concepts_1_1GenericConcept}{Generic} types is defined as follows\+:

A \doxylink{classAriadne_1_1Concepts_1_1ConcreteConcept}{Concrete} object of class X has a Concrete\+Concept\+::generic(...) method which returns \doxylink{namespaceAriadne_1_1Concepts_ab0e219279e6150966915e0c9bc4cd067}{Generic\+Type$<$\+X$>$}. Additionally, a concrete object may also be (explicity) converted to its generic type.

Usually the conversion will not be explicit, so a concrete object may be used whenever a generic is required.) From an object-\/oriented programming viewpoint, a concrete object is a subtype of its generic type, but as this may be difficult or inefficient to realise by subclassing, we do not require a subclassing relationship.

A concrete object is specified by its {\itshape properties}, which are given by the \doxylink{classAriadne_1_1Concepts_1_1ConcreteConcept_a2ab0950ae7e02ce972000bfb7df6d8bf}{Concrete\+Concept\+::properties()} method. It is constructible from its \doxylink{namespaceAriadne_1_1Concepts_ab0e219279e6150966915e0c9bc4cd067}{Generic\+Type} and its \doxylink{namespaceAriadne_1_1Concepts_a40d0fa2d6085c3aa7314aff0d295c25f}{Properties\+Type} as \doxylink{classAriadne_1_1Concepts_1_1ConcreteConcept_a73217b84243b1bf91a4617958b3f3062}{Concrete\+Concept\+::\+Concrete\+Concept(\+Generic\+Type, Properties\+Type)} If the \doxylink{namespaceAriadne_1_1Concepts_ab0e219279e6150966915e0c9bc4cd067}{Generic\+Type} is default-\/constructible, then it is also constructible from its \doxylink{namespaceAriadne_1_1Concepts_a40d0fa2d6085c3aa7314aff0d295c25f}{Properties\+Type} alone. Since after assignment, the properties are known, a concrete object is also {\itshape assignable} from its \doxylink{namespaceAriadne_1_1Concepts_ab0e219279e6150966915e0c9bc4cd067}{Generic\+Type} alone. Additionally, any binary operation between a concrete object and its generic type returns a concrete object, with the generic object first being cast to the concrete object\+: 
\begin{DoxyCode}{0}
\DoxyCodeLine{op(Concrete\ x,\ \mbox{\hyperlink{namespaceAriadne_1_1Concepts_ab0e219279e6150966915e0c9bc4cd067}{GenericType<Concrete>}}\ y)\ \{\ \textcolor{keywordflow}{return}\ op(x,\ Concrete(y,x.properties()));\ \}\ }

\end{DoxyCode}


The \doxylink{namespaceAriadne_1_1Concepts_a40d0fa2d6085c3aa7314aff0d295c25f}{Properties\+Type} may be a single class, or a {\itshape \doxylink{namespaceAriadne_a9ba6bbf66028bc5b9a5bcee1c9f7a2ca}{Tuple}} of classes {\ttfamily PRS}... . In the latter case, whenever a \doxylink{namespaceAriadne_a9ba6bbf66028bc5b9a5bcee1c9f7a2ca}{Tuple$<$\+PRS...$>$} is required as an argument, the individual properties may be substituted instead.

In general, \doxylink{classAriadne_1_1Concepts_1_1Effective}{Effective} types will be \doxylink{classAriadne_1_1Concepts_1_1GenericConcept}{Generic}, and \doxylink{classAriadne_1_1Concepts_1_1ConcreteConcept}{Concrete} types will be \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated}. The properties of a validated concrete object typically provide a grading of the representation, so can in principle be used instead of the \doxylink{classAriadne_1_1Concepts_1_1Effort}{Effort} to specify the accuracy of a computation.\hypertarget{type_system_page_exact_rounded}{}\doxysubsection{\texorpdfstring{Exact and rounded operations}{Exact and rounded operations}}\label{type_system_page_exact_rounded}
In Ariadne, core numerical types include \doxylink{classAriadne_1_1Integer}{Integer}, \doxylink{classAriadne_1_1Dyadic}{Dyadic} and \doxylink{classAriadne_1_1Rational}{Rational}, supported by computation-\/oriented classes \doxylink{namespaceAriadne_af915b9f1459c9691328efa71c6f39c6e}{Double\+Precision\+Float} and \doxylink{namespaceAriadne_a07966b67e613cc8779412beecb60651d}{Multiple\+Precision\+Float}. The former are \doxylink{structAriadne_1_1ExactTag}{Exact\+Tag} or Algebraic classes, since they support exact operations, typically with an algebraic signature, but not analytic operations which require a completion. The floating-\/point numbers are Rounded\+Tag or Concrete classes, and support {\itshape rounded} operations, based on the mathematical type the represent. Since these are primitive, countable data types, they support {\itshape exact} comparisons. However, this makes them {\itshape dangerous} in user code, so they should be wrapped in a Value, \doxylink{classAriadne_1_1Ball}{Ball}, \doxylink{classAriadne_1_1Bounds}{Bounds} or \doxylink{classAriadne_1_1Approximation}{Approximation} for most work.

Rounded numeric types support rounding {\itshape upward}, {\itshape downward}, and {\itshape to nearest}. Further, since current processors support builtin rounded arithmetic only through a global processor {\itshape rounding mode} state, they also support a {\itshape round} argument, which rounds to the current global rounding mode. These rounding arguments are placed {\itshape after} the input values in a constructor e.\+g. \doxylink{namespaceAriadne_af915b9f1459c9691328efa71c6f39c6e}{Float\+DP(\+Rational, Rounding\+Mode\+Type, Precision\+Type)}, but as the {\itshape first} argument in an operator e.\+g. add(\+Rounding\+Mode\+Type, Float\+DP, Float\+DP). All rounded operations in Ariadne need a rounding specifier (though this is currently not strictly enforced).\hypertarget{type_system_page_algebraic}{}\doxysubsection{\texorpdfstring{Algebraic operations}{Algebraic operations}}\label{type_system_page_algebraic}
Ariadne supports concepts for the algebraic classes of {\itshape rings}, {\itshape fields}, {\itshape lattices}, {\itshape vectors}, {\itshape algebras} and vectors of algebras. These support the usual mathematical operations, as detailed below. Further, {\itshape elementary} transcendental operations are supported for complete objects.

All operations are named. Where symbolic operators are traditionally used, such as {\itshape +} for {\itshape add}, a named version is also provided. An \doxylink{classAriadne_1_1Algebra}{Algebra} {\itshape A} has a Numeric\+Type {\itshape X}, and a \doxylink{classAriadne_1_1Vector}{Vector} has a Scalar\+Type. All types support assignment from an \doxylink{classAriadne_1_1Integer}{Integer}.

The supported basic operations on numbers are as follows\+:
\begin{DoxyItemize}
\item Ring {\ttfamily X\+:} {\ttfamily neg(\+X)-\/\texorpdfstring{$>$}{>}X}, {\ttfamily add(\+X,\+X)-\/\texorpdfstring{$>$}{>}X}, {\ttfamily mul(\+X,\+X)-\/\texorpdfstring{$>$}{>}X}; {\ttfamily nul}, {\ttfamily pos}, {\ttfamily sub}, {\ttfamily sqr}, {\ttfamily pow}.
\item Field {\ttfamily X\+:} {\ttfamily neg(\+X)-\/\texorpdfstring{$>$}{>}X}, {\ttfamily rec(\+X)-\/\texorpdfstring{$>$}{>}X}, {\ttfamily add(\+X,\+X)-\/\texorpdfstring{$>$}{>}X}, {\ttfamily mul(\+X,\+X)-\/\texorpdfstring{$>$}{>}X}; {\ttfamily sub}, {\ttfamily div}, {\ttfamily hlf}, {\ttfamily sqr}, {\ttfamily pow}.
\item Lattice {\ttfamily X\+:} {\ttfamily {\ttfamily max(\+X,\+X)-\/\texorpdfstring{$>$}{>}X},} {\ttfamily min(\+X,\+X)-\/\texorpdfstring{$>$}{>}X}; also {\ttfamily abs(x)-\/\texorpdfstring{$>$}{>}X} if negation is supported.
\item \doxylink{classAriadne_1_1Concepts_1_1Elementary}{Elementary} {\ttfamily X\+:} {\ttfamily {\ttfamily sqrt(\+X)-\/\texorpdfstring{$>$}{>}X},} {\ttfamily exp(\+X)-\/\texorpdfstring{$>$}{>}X}, {\ttfamily log(\+X)-\/\texorpdfstring{$>$}{>}X}, {\ttfamily sin(\+X)-\/\texorpdfstring{$>$}{>}X}, {\ttfamily cos(\+X)-\/\texorpdfstring{$>$}{>}X}, {\ttfamily tan(\+X)-\/\texorpdfstring{$>$}{>}X}, {\ttfamily atan(\+X)-\/\texorpdfstring{$>$}{>}X}.
\end{DoxyItemize}

The {\ttfamily nul} operator creates the zero element of the appropriate kind, {\ttfamily pos} creates a copy, {\ttfamily sub(x1,x2)=add(x1,neg(x2))}, {\ttfamily sqr(x)=mul(x,x)}, {\ttfamily div(x1,x2)=mul(x1,rec(x2))}, {\ttfamily hlf(x)=x/2}, and {\ttfamily abs(x)=max(x,neg(x))}.

Additionally, Ariadne supports {\itshape directed} \doxylink{classAriadne_1_1Concepts_1_1Lower}{Lower} and \doxylink{classAriadne_1_1Concepts_1_1Upper}{Upper} numbers, which only support monotone operations, and \doxylink{classAriadne_1_1Concepts_1_1Positive}{Positive} versions of all number types.

The {\ttfamily neg}, {\ttfamily add}, {\ttfamily sqrt}, {\ttfamily exp}, {\ttfamily log} {\ttfamily atan}, {\ttfamily max} and {\ttfamily min} operators are monotonic, and {\ttfamily mul} and {\ttfamily rec} are also monotonic on positive numbers. The {\ttfamily add}, {\ttfamily mul}, {\ttfamily rec}, {\ttfamily sqrt} and {\ttfamily atan} operators preserve positivity, {\ttfamily sqr}, {\ttfamily exp} and {\ttfamily abs} always yield positive answers, and {\ttfamily sqrt} and {\ttfamily log} require positive arguments. The {\ttfamily max} operator returns a positive value any of its arguments is positive, and {\ttfamily min} returns a positive value if all of its arguments are positive.

Algebraic types support the following arithmetic\+:
\begin{DoxyItemize}
\item \doxylink{classAriadne_1_1Vector}{Vector} {\ttfamily V\+:} {\ttfamily neg(\+V)-\/\texorpdfstring{$>$}{>}V}, {\ttfamily add(\+V,\+V)-\/\texorpdfstring{$>$}{>}V}, {\ttfamily mul(\+V,\+X)-\/\texorpdfstring{$>$}{>}V}; {\ttfamily sub(\+V,\+V)}, {\ttfamily mul(\+X,\+V)}, {\ttfamily div(\+V,\+X)}, {\ttfamily dot(\+V,\+V)}, {\ttfamily norm(\+V)} 
\item \doxylink{classAriadne_1_1Algebra}{Algebra} {\ttfamily A\+:} {\ttfamily neg(\+A)-\/\texorpdfstring{$>$}{>}A}, {\ttfamily add(\+A,\+A)-\/\texorpdfstring{$>$}{>}A}, {\ttfamily mul(\+A,\+A)-\/\texorpdfstring{$>$}{>}A}, {\ttfamily add(\+A,\+X)-\/\texorpdfstring{$>$}{>}A}, {\ttfamily mul(\+A,\+X)-\/\texorpdfstring{$>$}{>}A}; {\ttfamily sub(\+A,\+A)} etc.
\item \doxylink{classAriadne_1_1Concepts_1_1VectorAlgebra}{Vector\+Algebra} {\ttfamily VA\+:} {\ttfamily neg(\+VA)-\/\texorpdfstring{$>$}{>}VA}, {\ttfamily add(\+VA,\+VA)-\/\texorpdfstring{$>$}{>}VA}, {\ttfamily add(\+VA,\+VX)-\/\texorpdfstring{$>$}{>}VA}, {\ttfamily mul(\+VA,\+A)-\/\texorpdfstring{$>$}{>}VA}, {\ttfamily mul(\+VA,\+X)-\/\texorpdfstring{$>$}{>}VA}; etc
\end{DoxyItemize}

Additionally, a {\itshape normed} algebra has {\ttfamily norm(\+A)}, and a {\itshape graded} algebra has {\ttfamily A\+::degree()}. A {\itshape differential} algebra {\itshape DA} has a {\ttfamily derivative(\+DA, I)} for some index type {\itshape I}. A {\itshape function algebra} supports {\itshape coordinate} constructors as well as constants.

For \doxylink{classAriadne_1_1Concepts_1_1ConcreteConcept}{Concrete} objects, all relevant concrete-\/generic mixed operations are supported.\hypertarget{type_system_page_predicates_and_set_types}{}\doxysubsection{\texorpdfstring{Predicate and Set types}{Predicate and Set types}}\label{type_system_page_predicates_and_set_types}
As well as numbers, Ariadne also supports logical types. The usual \doxylink{classAriadne_1_1Boolean}{Boolean} type is used for the result of a {\itshape decidable} predicate, and the \doxylink{classAriadne_1_1Kleenean}{Kleenean} type for a {\itshape quasidecidable} predicate, which may be (provably) {\ttfamily true} or {\ttfamily false}, or of {\itshape unknown} or even {\itshape unknowable} truth {\ttfamily indeterminate}. The \doxylink{classAriadne_1_1Sierpinskian}{Sierpinskian} represents the result of a predicate which cannot (robustly) be falsified, such as the apartness/inequality relation $\neq$ on uncountable sets. The \doxylink{classAriadne_1_1LowerKleenean}{Lower\+Kleenean} type represents the result of a quasidecidable predicate which has only been checked for truth; for example, we may wish to prove the the maximum value of a function over a bounded interval is above some value, without spending the computational effort to provided a definitive result when this is not the case. Similarly, the \doxylink{classAriadne_1_1UpperKleenean}{Upper\+Kleenean} type represents the result of a quasidecidable predicate which has only been checked for falseness. The \doxylink{classAriadne_1_1Concepts_1_1Effective}{Effective} versions of the logical types support a check(\+Effort) method which returns a \doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated} version.
