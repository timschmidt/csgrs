In this section, we consider the model checking problem for discrete time systems without control or noise, as defined by a continuous function $f:\R^n\rightarrow \R^n$. We assume that the system has a set of initial points $X_0\subset \R^n$ and a safe set $S\subset\R^n$. Further, we assume that the set of initial points is {\itshape located}, which means that is supports predicates {\ttfamily intersects}, {\ttfamily separated} and {\ttfamily inside}, and that the safe set supports predicates {\ttfamily covers}, {\ttfamily separated} and {\ttfamily inside}.

We need a collection of {\itshape basic sets}, which for simplicity we assume to be boxes, and {\itshape enclosure sets}, which may, for example, be zonotopes.

The model checking problem for continuous-\/state-\/space systems differs from that of finite-\/state-\/space systems in that
\begin{DoxyItemize}
\item We cannot consider states directly. Instead, we can only work with finite abstractions of the system.
\item We can only work in a bounded (compact) part of the state space.
\item Abstract states can be refined infinitely often.
\item We usually need abstract states to be open or closed sets. In particular, they cannot form a partition of the state space, only an open cover or (closed) topological partition.
\item We cannot arbitrarily refine abstract states. Instead, we restrict the possible refinements of an abstract state. In the simplest case, there is only one possible way to refine an abstract state.
\item We cannot compute (or even represent) the successor (image) states of an abstract state completely. Instead, we can only compute an over-\/approximation to the actual set of (system or abstract) states.
\item We cannot decide whether a state is a subset of the safe set. However, given an abstract state, we may be able to prove that it is a subset of the safe set, or disjoint from the safe set. If an abstract state contains both safe and unsafe states, then so will at least one of the refined states.
\item We cannot decide wheter a state is an element of the initial set. Instead, given an abstract state, we may be able to prove that it the closure disjoint from the set of initial states, or that the interior intersects the initial set. Further, if the abstract states form a topological partition, then initial states lying on the boundary of the partition elements cannot be found, so in order to prove counterexamples, we need to use open sets of initial states.
\item In practice, we can only work to finite precision.
\end{DoxyItemize}\hypertarget{model_checking_page_counterexample_guided_abstraction_refinement}{}\doxysubsection{\texorpdfstring{Counterexample-\/\+Guided Abstraction Refinement (CEGAR)}{Counterexample-\/\+Guided Abstraction Refinement (CEGAR)}}\label{model_checking_page_counterexample_guided_abstraction_refinement}
In this section, we discuss how to modify counterexample-\/guided abstraction refinement for finite-\/state-\/space systems to the infinite-\/state-\/space setting.

For simplicity, we use boxes as the abstract states, and form a topological partition of the state space. We assume that given a box $B$, we can compute an enclosure $E$ containing $B$, that given an enclosure $E$, we can compute an enclosure containing $f(E)$, and given an enclosure $E$, we can compute a box $B$ containing $E$, and an outer-\/approximation of $E$ on a topological partition into boxes $\mathcal{B}$.

\begin{DoxyParagraph}{Abstraction data}

\end{DoxyParagraph}
Given an initial partition of the state space, we compute, for each box $B$\+:
\begin{DoxyItemize}
\item A set $[f](B)$ of {\itshape successor} boxes such that $B\textnormal{\textquotesingle}\cap f(B)\neq\emptyset \implies B\textnormal{\textquotesingle}\in [f](B)$.
\item Whether $B$ is a subset of $S$ ( $s=\top$), disjoint from $S$ ( $s=\bot$) or unknown/undecidable ( $s=\uparrow$).
\item Whether $B$ is a disjoint from $X_0$ ( $i=\bot$), a (small) neighbourhood of $B$ intersects $X_0$ ( $i=\top$) or unknown/undecidable ( $i=\uparrow$).
\end{DoxyItemize}

We then decide whether an abstract state (box) is safe.
\begin{DoxyItemize}
\item A box is definitely safe if every path starting from the box definitely remains in $S$ ( $v=\top$).
\item A box is definitely unsafe if every path starting from it definitely passes outside $S$ ( $v=\bot$).
\item Otherwise, we do not know whether a box is safe ( $v=\uparrow$).
\end{DoxyItemize}

To compute safety, we first compute boxes from which every path goes to a box with $s=\bot$. This can be done recursively, setting $v=\bot$ if $s=\bot$ or if $v=\bot$ for all sucessor states. A linear-\/time depth-\/first search algorithm can be used. A similar algorithm can treat the remaining states for $v=\uparrow$.

\begin{DoxyParagraph}{System safety}

\end{DoxyParagraph}

\begin{DoxyItemize}
\item If every box which possibly intersects the initial set is safe (i.\+e. has been validated; $v=\top$), then the system is safe.
\item If a box is definitely unsafe, and intersects the initial set, then the system is unsafe.
\item If a box is definitely unsafe, and possibly intersects the initial set, then the system is unsafe if the neighbourhood maps the the same set of boxes under one iterate. This must be the case for some neighbourhood. We then test either that the box is disjoint from the initial set, or the neighbourhood intersects the initial set.
\end{DoxyItemize}

Otherwise, there is a box which possibly intersects the initial set, and for which the evolution is possibly unsafe. An abstract counterexample is a sequence of boxes which ends in a possibly unsafe set. We choose such a sequence and try to prove that either it corresponds to a real counterexample, or remove the possibility of unsafeness by refinement.

\begin{DoxyParagraph}{Heurisitics}

\end{DoxyParagraph}
To choose the abstract counterexample to analyse, we may use the following heuristics\+:
\begin{DoxyItemize}
\item Shortest path
\item Starting box definitely contains an initial point
\item Ending box is definitely unsafe
\end{DoxyItemize}

To choose a box to split\+:
\begin{DoxyItemize}
\item Worst approximation\+: Choose the box $A_i$ maximising $\vec{d}(f(A_i),A_{i+1})$, where $\seq{d}(A,B)=\sup_{x\in A} \inf_\{y\in B\} d(x,y)$, the Hausdorff semi-\/distance.
\item Worst centre approximation\+: Choose the box $A_i$ maximising $d(f(m(A_i)),A_{i+1})$.
\end{DoxyItemize}

Both of the above heurisitics have the advantage that they eventually refine any possibly unsafe box, since they tend to choose relatively large boxes.


\begin{DoxyItemize}
\item No concrete trajectory. Compute $C_0=A_0$ and $C_{i+1}=\hat{f}(C_i)\cap A_{i+1}$ where $\hat{f}$ is an over-\/approximation to $f$. If possible, split $A_i$ for which $C_{i+1}=\emptyset$.
\end{DoxyItemize}

This is closest to the method described in Clarke et al, but might not be so appropriate in this case, since it is not guaranteed to find $i$, and repeated splitting might not eliminate spurious counterexamples,

To split the box\+:
\begin{DoxyItemize}
\item Split down the middle of the largest side (unique)
\item Test various splittings and choose the largest removing the abstract counterexample.
\end{DoxyItemize}

To update the system\+:
\begin{DoxyItemize}
\item Compute the abstract image of the new boxes
\item Update the abstract image of all boxes mapping to the old box
\item Update the {\ttfamily safe}, {\ttfamily initial} and {\ttfamily validated} properties. It may be possible to do this locally.
\end{DoxyItemize}

\begin{DoxyParagraph}{Counterexample checking}

\end{DoxyParagraph}
To test for a concrete counterexample\+:
\begin{DoxyItemize}
\item Iterate the initial box forward for $n$ steps as enclosures, and test whether the result is disjoint from the safe set.
\item If the initial box cannot be proved to intersect the initial set, enlarge the initial box.
\item To obtain better results, a subset of the initial box may be used, as long as it definitely intersects the safe set.
\end{DoxyItemize}

Note that testing for a concrete counterexample as above uses the abstract counterexample as a starting heuristic, but is, in fact, a completely different computation.

\begin{DoxyParagraph}{Advantages}

\end{DoxyParagraph}

\begin{DoxyItemize}
\item The worst approximation splitting should focus refinement in areas where the system modulus of continuity is high.
\item Verifying counterexamples separately avoids the need to use lower-\/approximations of the initial set. 
\end{DoxyItemize}
