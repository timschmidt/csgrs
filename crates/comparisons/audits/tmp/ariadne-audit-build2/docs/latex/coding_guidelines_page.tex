\begin{DoxyItemize}
\item Use C++ casts rather than C-\/style casts. i.\+e. use static\+\_\+cast$<$\+T$>$(x) and not (T)x.
\item Remember that identifiers beginning with two underscores \+\_\+\+\_\+\+XXX, \+\_\+\+\_\+xxx or an underscore and a capital letter \+\_\+\+Xxx are reserved for the compiler.
\item Each class should be in a single header file, which should include strongly related classes and methods.
\begin{DoxyItemize}
\item Source files xxx.\+cc should contain ordinary non-\/inline source code, internal code only used in the source file and explicit template instantiations.
\item Header files xxx.\+h should contain the interface, inline functions, templated code which is not explicitly instantiated and Doxygen documentation.
\item Header files xxx.\+decl.\+h should contain forward declarations.
\item Header files xxx.\+inl.\+h may be used for inline functions.
\item Header files xxx.\+tpl.\+h should contain templated code which is meant to be explicitly instantiated.
\end{DoxyItemize}
\item To ease template instantiation, non-\/member functions related to a class should not require explicit instantiation. They must then be in the main xxx.\+h file or xxx.\+inl.\+h, but may be simple forwarding functions to (static) class methods.
\item The use of a private static \+\_\+instantiate() method to enforce template instantiation does not work with all compilers and all optimization settings, and must not be used.

\hypertarget{coding_guidelines_page_initializerlists}{}\doxysubsubsection{\texorpdfstring{Initializer Lists}{Initializer Lists}}\label{coding_guidelines_page_initializerlists}
For many classes, it is useful to be able to initialise objects by providing lists of raw data. In C++, this is achieved using the \doxylink{namespaceAriadne_a8d51a34ecd8621e992f2470124281c93}{Initializer\+List\texorpdfstring{$<$}{<}T\texorpdfstring{$>$}{>}} template (which is an alias for {\ttfamily std\+::initializer\+\_\+list$<$\+T$>$}). For classes based on concrete numbers (which need a {\itshape precision} parameter for the initialisation, it is conventient to specify a list of generic numbers, and only give the precision parameter once. For example, for a \doxylink{classAriadne_1_1Vector}{Vector\texorpdfstring{$<$}{<}X\texorpdfstring{$>$}{>}} of elements of type {\ttfamily X}, which can be constructed from generic elements of type {\ttfamily Y} and properties of type {\ttfamily PR}, then we have a constructor {\ttfamily Vector(\+Initializer\+List$<$\+Y$>$,\+PR)}.

For not all types {\ttfamily X}, there may be suitable {\ttfamily Y} and {\ttfamily PR}, such a constructor is not always valid. One way of selectively providing this constructor is to take {\ttfamily Y} and {\ttfamily PR} as template parameters, which would yield a method {\ttfamily template$<$class Y, class PR$>$ Vector(\+Initializer\+List$<$\+Y$>$,\+PR)}. However, this disallows using different types in the initializer list, even if they can all be converted to a suitable common type.

Since the main use of such constructors is providing explicit values for testing, and the main class for numerical values are double-\/precision floats, we instead fix the type {\ttfamily Y} to be \doxylink{classAriadne_1_1ExactDouble}{Exact\+Double}, and only template on {\ttfamily PR}. Further, since a class may have many property parameters, we use a parameter pack {\ttfamily PRS}... instead of a single {\ttfamily PR}. This yields constructor\+: 
\begin{DoxyCode}{0}
\DoxyCodeLine{\textcolor{keyword}{template}<\textcolor{keyword}{class}...\ PRS>\ Vector(InitializerList<ExactDouble>,PRS...)}

\end{DoxyCode}


Similar constructors are provided for other list-\/based classes, such as \doxylink{classAriadne_1_1Matrix}{Matrix\texorpdfstring{$<$}{<}X\texorpdfstring{$>$}{>}} and \doxylink{classAriadne_1_1Expansion}{Expansion\texorpdfstring{$<$}{<}I,X\texorpdfstring{$>$}{>}}.
