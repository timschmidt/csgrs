\hypertarget{overview_page_overview_reachability}{}\doxysubsection{\texorpdfstring{Reachability Analysis of Hybrid Systems}{Reachability Analysis of Hybrid Systems}}\label{overview_page_overview_reachability}
The main functionality of Ariadne is to perform reachability analysis and verification of hybrid systems. A {\itshape hybrid system} is a dynamic system in which continuous evolution is interspersed with discrete jumps. The state space of a hybrid system is of the form $X=\bigcup_{q\in Q} \{q\}\times \R^{n_q}$ with $Q$ a finite set of {\itshape locations}. The evolution of a hybrid system proceeds via a differential equation $\dot{x}(t) = f_q(x(t))$ in location $q$ until a {\itshape guard condition} $g_e(x)\geq 0$ is satisfied, in which case the {\itshape event} $e$ occurs, the location jumps to a target location $q\textnormal{\textquotesingle}=\tau(q,e)$ and the continuous state jumps to $x\textnormal{\textquotesingle}=r_{q,e}(x)$.

A {\itshape trajectory} or {\itshape execution} of a hybrid system comprises continuous evolution interspersed with discrete events. We let $t_0$ be the {\itshape starting time} (canonically $t_0=0$) and $t_n$ the time when the $n^\mathrm{th}$ event $e_n$ occurs. Since more than one event may occur at the same time, we keep track of both the total number of events as well as the elapsed time when describing a trajectory. A trajectory is therefore a partial function $\xi(t,n)$ defined whenever $t_n\leq t\leq t_{n+1}$. The domain of $\xi$ is a {\itshape hybrid time domain} $T=\{ (t,n)\in\R^+\times\Z^+ \mid t\in[t_n,t_{n+1}]$. A trajectory is {\itshape Zeno} if the total number of event $N$ equals $\infty$, and $\lim_{n\to\infty} t_n < \infty$.

In {\itshape reachability analysis} we are given an {\itshape initial set} $X_0 \subset X$, and aim to compute the set of points which are reachable by a trajectory starting in $x_0$. The reachability analysis may be performed over a {\itshape finite} time interval, in which case a bound on the total time $T$ and the maximum number of events $N$ is given, or over an {\itshape infinite} time interval.

In both cases, we can compute either an over-\/approximation to the reachable set $R$, or a {\itshape lower} approximation. A set $A$ is said to be an $\epsilon$-\/lower approximation to $S$ if $A\subset N_\epsilon(S)$, and an over-\/approximation if $A\supset S$. For general systems it is impossible to compute a sequence of over-\/approximations converging to the infinite-\/time reachable set. Instead, we compute over-\/approximations to the reachable set which converge to the {\itshape chain-\/reachable set} as the accuracy parameters governing the computation are improved.

\hypertarget{overview_page_overview_function}{}\doxysubsection{\texorpdfstring{Function Calculus}{Function Calculus}}\label{overview_page_overview_function}
The computational kernel of Ariadne is based on a calculus of continuous functions on Euclidean space. The core type is of (multivariable, vector-\/valued) functions $f:\R^n\rightarrow\R^m$. These functions can be built from scalar-\/valued functions $\R^n\rightarrow\R$ componentwise, starting from the constant functions $f(x_1,\ldots,x_n)=c$, the coordinate projection functions $f(x_1,\ldots,x_n)=x_i$, arithmetical operations $+,-,\times,\div$, the absolute value operation $|x|$ and simple functions such as $\mathrm{sqrt}$, $\exp$, $\log$ and $\sin$.

The results of operations on functions are expressed in terms of {\itshape interval functions} on bounded domains. An interval function is a map $\mathbb{IF}^n\rightarrow\mathbb{IF}^m$ where $\mathbb{IF}$ is the set of intervals in $\R$ with endpoints in a subset $\mathbb{F}$ of $\R$. An interval function $\hat{f}:\mathbb{IF}^n\rightarrow\mathbb{IF}^m$ is an {\itshape interval extension} of $f:\R^n\rightarrow\R^m$ if for every box $\ivl{x}=[a_1,b_1]\times\cdots\times[a_n,b_n]\in\mathbb{IF}^n$ and every $x\in\ivl{x}$, we have $f(x)\in \hat{f}(\ivl{x})$.

If the result of an exact operation is a continuous function $f:U\fto\R^m$ where $U$ is an open subset of $\R^n$, then the computed solution is typically an interval function $\hat{f}:\IF^n\fto\IF^m$ which is a valid interval extension of $f$ on a box $D\subset U$.

The main operations which Ariadne can perform are
\begin{DoxyItemize}
\item Solution of differential equations\+: Given a differential equation of the form $\dot{x}=f(x)$, computes the flow $\phi(x,t)$ satisfying $\phi(x,0)=x$ and $\dot{\phi}(x,t) = f(\phi(x,t))$.
\item Solution of (parameterised) algebraic equations\+: Given an algebraic equation $f(a,x)=0$, find a function $h(a)$ satisfying $f(a,h(a))=0$.
\item Nonlinear feasibility problems\+: Given a set of nonlinear constraints $g_i(x)\in C_i$, determine whether there exists a solution with $x\in D$.
\item Solution of nonlinear programming problems\+: Given a nonlinear programming problem $ \max f(x) \text{ such that } x\in D,\ g(x)\leq 0\text{ and } h(x) = 0 $ where $D$ is a bounded domain, find all (local) solutions.

In order to use Ariadne for reachability analysis, it is first necessary to build a hybrid system. The \doxylink{classAriadne_1_1HybridAutomaton}{Hybrid\+Automaton} class is the main Ariadne class for describing hybrid systems as a single hybrid automaton. A Monolithic\+Hybrid\+Automaton comprises \doxylink{classAriadne_1_1DiscreteMode}{Discrete\+Mode} and \doxylink{classAriadne_1_1DiscreteTransition}{Discrete\+Transition} objects to describe the modes (including continuous dynamics and invariants) and the discrete transitions (describing guards/activation predicates and reset relations.

An Ariadne automaton must be built explicitly using the \doxylink{classAriadne_1_1HybridAutomaton_ab362c7846c09f3962b39982442849d7d}{{\ttfamily new\+\_\+mode} }, \doxylink{classAriadne_1_1HybridAutomaton_ad6edf75d890f36ed0d5abf9d34b51266}{{\ttfamily new\+\_\+invariant} } and \doxylink{classAriadne_1_1HybridAutomaton_a761675be8c1692d45f5c4060f109a9fa}{{\ttfamily new\+\_\+transition} } methods.

All resets, flows and guards are specified using {\itshape functions}. A function is just a mapping from $\R^m$ to $\R^n$. Unfortunately, since Ariadne uses specialised automatic differentiation functionality, an Ariadne function cannot be specified directly from a C++ function, but must be defined using the a function object. The \doxylink{group__FunctionModule_ga97dec0be54bdb27609f9925b055e35dc}{Scalar\+Function} and \doxylink{group__FunctionModule_gae5d2f69ea172c6a2dfa7d2f12f700737}{Vector\+Function} classes can be used to build and represent simple functions. The \doxylink{classAriadne_1_1ScalarUserFunction}{{\ttfamily \doxylink{classAriadne_1_1ScalarUserFunction}{Scalar\+User\+Function$<$\+F$>$}} } and \doxylink{classAriadne_1_1VectorUserFunction}{{\ttfamily \doxylink{classAriadne_1_1VectorUserFunction}{Vector\+User\+Function$<$\+F$>$}} } can be used to wrap more complex user function objects to conform to the Ariadne interface.\hypertarget{overview_page_overview_analyser}{}\doxysubsection{\texorpdfstring{Building an Evolver or Analyser}{Building an Evolver or Analyser}}\label{overview_page_overview_analyser}
In order to analyse a hybrid system, we need an {\itshape Evolver} or {\itshape Analyser} class. An Evolver class is used to perform simulations, and computes the evolution up to a given time starting from an initial {\itshape enclosure} set. An Analyser class is used to perform global analysis, and computes the evolution starting from an arbitrary given set. Internally, an Analyser class typically uses an Evolver to perform the evolution, and then performs a discretization of the evolved set on a grid.

An evolver class satisfies the interface \doxylink{classAriadne_1_1EvolverInterface}{{\ttfamily \doxylink{classAriadne_1_1EvolverInterface}{Evolver\+Interface$<$\+SYS,\+ES$>$}} }, where {\ttfamily ES} is the template parameter giving the type used for the enclosure sets. The \doxylink{classAriadne_1_1HybridEvolverInterface}{Hybrid\+Evolver\+Interface } class is an interface for evolvers for hybrid systems using the type {\ttfamily \doxylink{classAriadne_1_1HybridEnclosure}{Hybrid\+Enclosure}} to specify the continuous part of the enclosure set. To build an Evolver class, we need to give {\itshape evolution parameters} to specify the accuracy of the computation. The evolution parameters are passed using the evolver\textquotesingle{}s configuration class. Note that not all parameters need be used by a given Evolver class.

A reachability analyser class satisfies the interface \doxylink{classAriadne_1_1ReachabilityAnalyserInterface}{{\ttfamily \doxylink{classAriadne_1_1ReachabilityAnalyserInterface}{Reachability\+Analyser\+Interface$<$\+SYS$>$}} }. The class \doxylink{classAriadne_1_1HybridReachabilityAnalyser}{Hybrid\+Reachability\+Analyser} may be used to perform reachability analysis of hybrid systems. It can be constructed from a \doxylink{classAriadne_1_1HybridEvolverInterface}{Hybrid\+Evolver\+Interface} class.

We use Evolver and Analyser classes rather than functions to perform the analysis since different methods require different user parameters to specify the accuracy.
