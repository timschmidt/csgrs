\doxysubsubsection{Description}
A class representing an enclosure for a hybrid evolution. Handles progress, activation and guard constraints internally. The set is represented as the image of a box $D$ under a function model $\xi(s)=\hat{f}(s)$, under the constraints $\hat{c}(s) \leq 0$ and $\hat{e}(s)=0$. Also keeps track of the current time $\tau(s)=\hat{t}(s)$. 

In other words, \[ S=\{ \hat{f}(s);\  \hat{t}(s) \mid s\in D \mid \hat{c}(s) \leq 0 \ \wedge \hat{e}(s)=0 \} . \] In the following documentation, we sometimes write $\xi(s)$ for $\hat{f}(s)$ and $\tau(s)$ for $\hat{t}(s)$. yielding \[ S=\{ \xi(s);\  \tau(s) \mid s\in D \mid \rho(s) \in C \} . \]

{\bfseries{Rationale\+:}}\texorpdfstring{$<$}{<}\begin{DoxyParagraph}{\texorpdfstring{$>$}{>}}
{\bfseries{Parameterisation of the time specifier}} When computing a flow step, the evolution time can be given either as a function $\varepsilon(x)$ of the state, or as an absolute final time $\omega(s)$ of the parameters. The rationale for this difference is that we often use the $\varepsilon$ form when computing the flow up to a crossing with a guard, in which case the time depends purely on the state, and it may be possible to simplify the constraints by expressing them in terms of the current states (in an implementation in which intermediate states are considered explicitly). The rationale for using a parameterised form with independent variable $s$ is that this is needed to distinguished different states based on crossings with the guard sets. The rationale for using a final time $\omega(s)$ as a final time is that this allows us to remove errors in the elapsed time $\tau(s)$.
\end{DoxyParagraph}
A possible extension would be to allow $\omega(s)$ to depend on intermediate variables $x_i$ at previous stages. The reason for not doing this is that it would enforce a policy for tracking intermediate states, which we do not want to insist on during an implementation.
