\hypertarget{hybrid_automaton_page_0_4}{}\label{hybrid_automaton_page_0_4}\index{Building a Hybrid Automaton (version 0.4)@{Building a Hybrid Automaton (version 0.4)}}
Building a hybrid automaton in Ariadne involves two main steps. We first define the real-\/valued functions used in the automaton, and then build the automaton from these pieces. However, first we need to know about the core numeric and linear algebra types used by Ariadne.\hypertarget{hybrid_automaton_page_0_4_hybrid_automaton_core}{}\doxysubsection{\texorpdfstring{Ariadne Core Types}{Ariadne Core Types}}\label{hybrid_automaton_page_0_4_hybrid_automaton_core}
\hypertarget{hybrid_automaton_page_0_4_hybrid_automaton_numeric}{}\doxysubsubsection{\texorpdfstring{Numerical Types}{Numerical Types}}\label{hybrid_automaton_page_0_4_hybrid_automaton_numeric}
Ariadne supports \doxylink{group__NumericModule_gad8d641e86f517dc6189876d9d1a6345a}{Float\+Approximation} and \doxylink{group__NumericModule_ga1e049524e162af01e451c9183315a982}{Float\+Bounds} types, representing an approximate floating-\/point value, and an approximation to a real value given by an interval $[l,u]$.

Additionally, Ariadne supports \doxylink{classAriadne_1_1Integer}{Integer} and \doxylink{classAriadne_1_1Rational}{Rational} types if the Gnu Multiple-\/\+Precision library (GMP) is available. However, these types are typically not used for defining systems.\hypertarget{hybrid_automaton_page_0_4_hybrid_automaton_vector_matrix}{}\doxysubsubsection{\texorpdfstring{Vectors and Matrices}{Vectors and Matrices}}\label{hybrid_automaton_page_0_4_hybrid_automaton_vector_matrix}

\hypertarget{hybrid_automaton_page_0_4_hybrid_automaton_functions}{}\doxysubsection{\texorpdfstring{Ariadne Functions}{Ariadne Functions}}\label{hybrid_automaton_page_0_4_hybrid_automaton_functions}
An Ariadne \doxylink{classAriadne_1_1HybridAutomaton}{Hybrid\+Automaton} object is built out of vector-\/valued functions on Euclidean space $f:\R^m\rightarrow\R^n$. Since Ariadne internally needs to be able to evaluate the function on different data types, all functions used in an Ariadne \doxylink{classAriadne_1_1HybridAutomaton}{Hybrid\+Automaton} must inherit from the Scalar\+Function\+Interface or Vector\+Function\+Interface class. The \doxylink{group__FunctionModule_ga97dec0be54bdb27609f9925b055e35dc}{Scalar\+Function} and \doxylink{group__FunctionModule_gae5d2f69ea172c6a2dfa7d2f12f700737}{Vector\+Function} classes can be used to build general-\/purpose functions. A number of builtin function types are provided, including Identity\+Function, Scalar\+Constant\+Function, Scalar\+Affine\+Function and Scalar\+Polynomial\+Function. Additionally, a \doxylink{classAriadne_1_1ScalarUserFunction}{Scalar\+User\+Function$<$\+T$>$ } template is provided to facilitate the creation of more complicated nonlinear functions.\hypertarget{hybrid_automaton_page_0_4_hybrid_automaton_builtin_functions}{}\doxysubsubsection{\texorpdfstring{Builtin Functions}{Builtin Functions}}\label{hybrid_automaton_page_0_4_hybrid_automaton_builtin_functions}

Finally, build up the system using the methods\+:
\begin{DoxyItemize}
\item \doxylink{classAriadne_1_1HybridAutomaton_ab362c7846c09f3962b39982442849d7d}{Hybrid\+Automaton\+::new\+\_\+mode(Discrete\+State location, Function\+Interface dynamic)}
\item \doxylink{classAriadne_1_1HybridAutomaton_ad6edf75d890f36ed0d5abf9d34b51266}{Hybrid\+Automaton\+::new\+\_\+invariant(Discrete\+State location, Function\+Interface predicate)}
\item \doxylink{classAriadne_1_1HybridAutomaton_a761675be8c1692d45f5c4060f109a9fa}{Hybrid\+Automaton\+::new\+\_\+transition(Discrete\+Event event, Discrete\+State source, Discrete\+State target, Function\+Interface reset, Function\+Interface guard, bool urgency)}
\end{DoxyItemize}

bearing in mind\+:
\begin{DoxyItemize}
\item Every mode must correspond to different discrete state.
\item The {\itshape dynamic} in location $q$ must be a function $f:\R^{n_q}\rightarrow \R^{n_q}$, so as to define a differential equation $\dot{x}=f(x)$. The constant $n_q$ is the {\itshape dimension} of the location.
\item The {\itshape predicate} defining an invariant in location $q$, and the {\itshape guard} of a transition with {\itshape source} $q$ must scalar functions $\R^{n_q}\rightarrow\R$
\item There may be multiple invariants in a given location.
\item There can be at most one transition with a given {\itshape event} and {\itshape source}.
\item The {\itshape reset} of a transition with {\itshape source} $s$ and {\itshape target} $t$ must be a function $r:\R^{n_s}\rightarrow \R^{n_t}$.
\item If {\itshape urgency} flag is true, then the transition occurs as soon as the {\itshape guard} is positive. Otherwise, the transition is {\itshape permissive}, and occurs nondeterministically at any time (or not at all).
\end{DoxyItemize}

The main restriction to the invariants and guards is that they must be scalar functions. This is due to the way Ariadne performs event detection. These restrictions will be lifted in a later version of Ariadne.
