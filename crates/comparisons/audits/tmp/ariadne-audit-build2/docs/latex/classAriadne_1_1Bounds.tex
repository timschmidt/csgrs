\subsubsection*{template$<$class F$>$\newline
class Ariadne\+::\+Bounds$<$ F $>$}
\doxylink{classAriadne_1_1Concepts_1_1Validated}{Validated} bounds on a number with floating-\/point endpoints supporting outwardly-\/rounded arithmetic. 

Note that direct construction from a floating-\/point number is prohibited, since {\ttfamily Float\+DPBounds(3.\+3,dp)} would the singleton interval $[3.2999999999999998224,3.2999999999999998224]$ (the constant is first interpreted by the C++ compiler to give a C++ {\ttfamily double}, whereas {\ttfamily Float\+DPBounds(3.\+3\+\_\+decimal,dp)} yields the interval $[3.2999999999999998224,3.3000000000000002665]$ enclosing $3.3$.

\doxylink{namespaceAriadne_a0e36a4c4b857737f71444bff61a9edb6}{Comparison} tests on {\ttfamily \doxylink{classAriadne_1_1Bounds}{Bounds}} use the idea that an interval represents a single number with an unknown value. Hence the result is of type {\ttfamily \doxylink{classAriadne_1_1ValidatedKleenean}{Validated\+Kleenean}}, which can take values \{ {\ttfamily True}, {\ttfamily False}, {\ttfamily Indeterminate} \}. Hence a test $[\underline{x},\overline{x}]\leq [\underline{y},\overline{y}]$ returns {\ttfamily True} if $\overline{x}\leq \underline{y}$, since in this case $x\leq x$ whenever $x_1\in[\underline{x},\overline{x}]$ and $y\in[\underline{y},\overline{y}]$, {\ttfamily False} if $\underline{x}>\overline{y}$, since in this case we know $x>y$, and {\ttfamily Indeterminate} otherwise, since in this case we can find $x,y$ making the result either true or false. In the case of equality, the comparison $[\underline{x},\overline{x}]$== $[\underline{y},\overline{y}]$ only returns {\ttfamily True} if both intervals are singletons, since otherwise we can find values making the result either true of false. To test equality of representation, use {\ttfamily same(x,y)} 

To obtain the lower and upper bounds of the possible values, use {\ttfamily x.\+lower()} and {\ttfamily x.\+upper()}. To obtain a best estimate of the value, use {\ttfamily x.\+value()}, which has an error at most {\itshape x.\+error()}. If $v$ and $e$ are the returned value and error for the bounds $[l,u]$, then it is guaranteed that $v-e\leq l$ and $v+e\geq u$ in exact arithmetic.

To test if the bounds contain a number , use {\ttfamily models(\+Bounds$<$\+F$>$,\+F)}, and to test if bounds are inconsistent use {\ttfamily inconsistent(x,y)}, and to test if {\ttfamily x} provides a better approximation, use {\ttfamily refines(x,y)}. \begin{DoxySeeAlso}{See also}

\begin{DoxyParagraph}{Python interface}

\end{DoxyParagraph}
In the Python interface, Ariadne validated bounds can be constructed from Python literals of the form {\ttfamily \{a\+:b\}} or (deprecated) {\ttfamily }\mbox{[}a,b\mbox{]} . The former is preferred, as it cannot be confused with literals for other classes such as \doxylink{classAriadne_1_1Vector}{Vector} and \doxylink{classAriadne_1_1Array}{Array} types. Automatic conversion is used to convert \doxylink{group__NumericModule_ga1e049524e162af01e451c9183315a982}{Float\+Bounds} literals of the form {\ttfamily \{a},b\} to an \doxylink{group__NumericModule_ga1e049524e162af01e451c9183315a982}{Float\+Bounds} in functions.

Care must be taken when defining intervals using floating-\/point coefficients, since values are first converted to the nearest representable value by the Python interpreter. ~\newline
