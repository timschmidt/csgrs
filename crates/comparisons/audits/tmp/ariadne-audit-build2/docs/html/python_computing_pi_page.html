Computing Pi

On this page, we illustrate the use of Ariadne's Numeric module by computing \(\pi\). The full code for this example can be found in the file computing_pi.py,

There are many formulae for pi. We will use the identity tan(pi/6)=1/sqrt(3), yielding pi=6*atan(1/sqrt(3))

>>> r = 6*atan(rec(sqrt(3)))

Displaying r shows that it is represented by a symbolic formula, and has type the Ariadne class Real

>>> print("r:",r,type(r))
r: mul(6,atan(rec(sqrt(3)))) <class 'pyariadne.Real'>

To compute \(\pi\), we first need to give the accuracy of the approximation we want. Let's assume we want 20 binary digits of accuracy, so the absolute error should be less than \(2^{-20}\).

>>> acc = Accuracy(1/two**20)

Note that Ariadne does not allow us to use

>>> acc = Accuracy(1/2**20) # Wrong!

which yields an error

TypeError: __init__(): incompatible constructor arguments. The following argument types are supported:
1. pyariadne.Accuracy(arg0: Ariadne::Dyadic)
Ariadne
Top-level Ariadne namespace.
Definition algebra.cpp:35

since the 1/2**20 is evaluated as a Python float, which is subject to rounding errors and may be inaccurate. (In this case there happens to be no rounding error, but since Python yields a result of type float, the constructor is still disabled.)

We can then compute r to the given accuracy:

>>> v = r.compute(acc)
>>> print("v":",v,type(v))
v: [3.14159265358979222781954376841895282268524169921875:3.141592653589794448265593018732033669948577880859375] <class 'pyariadne.ValidatedReal'>

The type of the result v is ValidatedReal, which means that v provides a guaranteed set of possible values for the true value of r. In this case, the set is given as an interval of values. Comparing significant digits, the result is \(3.14159265358979[22278...\!:\!44482...]\), so has 15 correct decimal places, which is more than requested. The bounds of the interval are given as their exact values. Internally, they may be represented by dyadic numbers.

If we want to work efficiently with \(\pi\), it is better to convert to a concrete representation using floating-point numbers. Ariadne supports standard double-precision numbers. Double-precision bounds for r can be extracted from v as a class FloatDPBounds by

>>> pr = double_precision
>>> x = v.get(pr)
>>> print("x":",x,type(x))
x: 3.14159265358979[222:445] <class 'pyariadne.FloatDPBounds'>

We can then work using x to give bounds for calculations about \(\pi\). For example, we can compute \(\sin(\pi/6)\) by

>>> print("sin(x/6):",sin(x/6),type(sin(x/6)))
sin(x/6): 0.[499999999999999611:500000000000000556] <class 'pyariadne.FloatDPBounds'>
>>> print("sin(x/4):",sin(x/4),type(sin(x/4)))
sin(x/4): 0.707106781186547[128:906]

However, since x stores only limited-accuracy bounds for \(\pi\), the accuracy of further computations using x is also limited.

To work using more accuracy, we can use a higher accuracy. Suppose we want to work compute to 120 binary places of accuracy, which is roughly 40 decimal places.

>>> acc = Accuracy(1/two**120) # Wrong!
>>> v = r.compute(acc)
>>> print("v":",v,type(v))
v: [3.141592653589793238462643383279502884171776471280999285698823952014915457789560348004186118853198195211007259786128997802734375:3.1415926535897932384626433832795028842305511888221136610972607788760277416804936258427904949286357805249281227588653564453125] <class 'pyariadne.ValidatedReal'>

So we find \(v=3.141592653589793238462643383279502884[17177\cdots \!:\! 23055...] \subset 3.141592653589793238462643383279502884[17\!:\!24] \). We could again extract double-precision bounds

>>> x = v.get(double_precision)
x: 3.141592653589793[115:561]

but this loses the accuracy of the computation, since double-precision only allows \(53\) significant binary places, roughly \(16\) significant decimal places.

To keep the high accuracy, we can instead extract bounds in a multiple-precision floating-point type, yielding a FloatMPBounds object. If we want 128 significant binary places, we use

>>> pr = precision(128)
>>> pr = multiple_precision(128)
>>> pr = MultiplePrecision(128)
>>> x = v.get(pr)
>>> print("x":",x,type(x))
x: 3.141592653589793238462643383279502884[1:3] <class 'pyariadne.FloatMPBounds'>

To see the internal structure of x, we can use Python's representation:

>>> print("repr(x)":",repr(x))
repr(x): FloatMPBounds(3.1415926535897932384626433832795028842,3.1415926535897932384626433832795028842)

To see the precision of x, we can use

>>> print("x.precision():",x.precision())
MultiplePrecision(128)

Again we can work with x as an approximation to \(\pi\).

>>> print("sin(x/6):",sin(x/6),type(sin(x/6)))
sin(x/6): 0.[499999999999999611:500000000000000556] <class 'pyariadne.FloatDPBounds'>
>>> print("sin(x/4):",sin(x/4),type(sin(x/4)))
sin(x/4): 0.707106781186547524400844362104849039[27:30]

Note that we could instead compute \(\pi\) directly using a given precision from the formula used, since Ariadne evaluates all expressions using a "concrete" FloatBounds class using this concrete class.

>>> three=FloatMPBounds(3,precision(128))
>>> x=6*atan(1/sqrt(three))
>>> print("x:",x,type(x))
x: 3.141592653589793238462643383279502884[1:3] <class 'pyariadne.FloatMPBounds'>

Note that Ariadne has a builtin constant pi, which should be used in real code!!

>>> print("pi:",pi,type(pi))
pi: mul(4,atan(1)) <class 'pyariadne.Real'>
>>> acc=Accuracy(1/two**20)
>>> print("pi.compute(acc):",pi.compute(acc))
pi.compute(acc): [3.141592653589793115997963468544185161590576171875:3.141592653589793560087173318606801331043243408203125]
