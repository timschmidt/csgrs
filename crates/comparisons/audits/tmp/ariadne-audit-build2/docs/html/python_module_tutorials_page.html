On this page, we illustrate how to use Ariadne via the Python interface.

  • A guide to working with numbers is given in the Numeric module tutorial.
  • A guide to working with functions is given in the Function module tutorial.

Links are given to the main classes used in the tutorials. The documentation for these classes is automatically generated from comments in the C++ code. To help Python users unfamiliar with C++ understand this documentation, a guide on the main differences between C++ and Python can be found on the Python Interface page.

The Ariadne module

First, import the Ariadne module. For ease-of-use, the from version of import is recommended:

from pyariadne import *

To see all the classes and functions available in Ariadne, type:

print(dir(ariadne))

The Numeric module

The full code of this tutorial is given in the file python/tutorials/numeric_tutorial.py.

In this tutorial, we will study iterated dynamical systems of the form \(x_{n+1}=f(x_n)\).

We define a function which computes n iterates of f starting at x0:

0def compute_iterates(f,x0,n):
30 xs=[x0]
31 for i in range(n):
32 xs.append(f(xs[-1]))
33 return xs

Exact arithmetic

Ariadne has a number of classes supporting exact arithmetical operations, namely Integer, Dyadic, Decimal and Rational. Further, there is a Real number class which also supports elementary transcendental operations; the use of Real is illustrated in Effective real arithmetic section. All these numeric classes support standard arithmetical operators. A full list of these operations is given in the list of supported operations. Since these are easiest to understand, we will start here.

Let's study the unimodal function \(f(x)=ax(b-x)\) with parameters \(a=3.625\) and \(b=1\).

Since \(b\) is an integer, it can be represented by the Ariadne Integer class. Like Python's int type (but unlike C++ int), Ariadne's Integer class can hold arbitrary-sized numbers.

34 b=Integer(1)

The parameter \(a\) is a dyadic number, of the form \(p/2^q\) where \(p\) and \(q\) are integers; equivalently, a number with a terminating binary expansion, since \(a=3.625=29/2^3=11.101_2\). We can therefore use that Dyadic class to represent \(a\):

46 a=Dyadic(29,3) # Constructs the number 3.625=29/2^3.

There are alternative ways to construct a dyadic number using the builtin constant two:

50 a=29/two**3 # Alternative syntax for 3.625=29/2^3
51 a=3+5/two**3 # Alternative formula for 3.625=3+5/2^3

Note that the following code is not valid:

a=Dyadic(3.625)

since a Python float value may typically represent the result of an approximate computation, and should not be used in an exact context.

We can define \(f\) as a basic Python function. (Ariadne has its own builtin function classes; see the Function Module and python_function_tutorial for more details.)

52 def f(x):
55 return a*x*(b-x)

Let's start the iteration at \(x_0=0.5\). This is also a dyadic number, so we can compute using dyadic arithmetic:

56 x0=1/two
59 xs=compute_iterates(f,x0,8)

Looking at the values, we see that the length of the iterates approximately doubles at each step, quickly leading to representations which are too large to efficiently work with.

We can iterate the map using rational arithmetic by defining the initial point as a rational number.

60 x0=Rational(1,2)

We then compute iterates

64 xs=compute_iterates(f,x0,8)

Here too, the length of the denominator roughly doubles every iterate.

In general, the Dyadic and Rational class are useful for problem specification, but unsuitable for computations. In many cases, the result cannot be expressed exactly as a number of the same kind, and even if it can be, the length of the description typically grows rapidly through the computation.

The issue with 'float's

Since Python's builtin float class uses rounded arithmetic, such numbers may not be an exact representation of a value, leading to unsafe computation. If a Python float is indeed an exact value, (e.g. \(3.625\) is an exact double-precision floating-point number), this must first be converted to an Ariadne ExactDouble class:

65 a=ExactDouble(3.625)
73 a=x_(3.625)

Numbers which are not exactly representable in double-precision should be converted to the Decimal class instead.

74 a=Decimal(3.625)

or as string literals

76 a=Decimal("3.625")

The Decimal number class is intended to allow input of human-readable decimal values, and not for computation, though it does support standard arithmetical operations.

Python float numbers can also be converted to Ariadne numbers by using Python equivalents dy_, dec_ and q_ of the C++ literals _dy, _dec and _q.

77 a=dy_(3.625)
79 a=dec_(3.625)
80 a=q_(3.625)

Python int numbers can be converted to Ariadne Integers by using the Python equivalent z_ of the C++ literal _z.

81 b=z_(1)

Hence an alternative way of defining \(f\) would be as

82 a=Decimal(3.625)
84 b=Integer(1)
85 def f(x):
86 return a*x*(b-x)

or more succinctly as

87 def f(x):
89 return dec_(3.625)*x*(1-x)

Floating-point arithmetic

Computations in Ariadne are usually most efficiently performed using floating-point number types. Ariadne supports the FloatDP and FloatMP types, which are respectively based on builtin IEEE double-precision floating-point numbers, and multiple-precision floating-point numbers from the MPFR library.

Raw floating-point numbers only support rounded arithmetic, so are best avoided in user code. Instead, they can be used in safe correctly-rounded generic types, notably Bounds<F>, Ball<F,FE>, and Approximation<F>, though Value<F>, UpperBound<F>, LowerBound<F> are also available.

In Python, the template parameter is appended to the class name, so FloatDPBounds is the Python name for Bounds<FloatDP>, and FloatMPBounds is the name for Bounds<FloatMP>.

Note
In a future version, it is planned to use square brackets for Python equivalents to C++ template classes, so C++ Bounds<FloatMP> would translate to Python Bounds[FloatMP].

The Bounds classes support outward-rounded interval arithmetic; see Interval Arithmetic for details.

To construct a Bounds object based on FloatDP or FloatMP, we must always provide the precision as one of the arguments. We can iterate the system using double-precision interval arithmetic by taking initial condition:

90 x0=FloatDPBounds(q_(1/2),double_precision)

and then iterating the function

96 x0=Bounds[FloatDP](q_(1/2),double_precision)
97 xs=compute_iterates(f,x0,16)

Note that the iterates are also of clas FloatDPBounds; this is because binary operations between exact values such as Rational, and "concrete" values based on a Float always return a concrete value. Unlike rational arithmetic, the length of the representation does not change, but the accuracy decreases through the computation.

To attain more accuracy, the FloatMPBounds class can be used:

98 x0=Bounds[FloatMP](q_(1/2),precision(bits=192))
102 xs=compute_iterates(f,x0,16)

Guaranteed over-approximations can also be computed using the Ball classes, which use an approximation of the form \(x=x_c\pm e_x\). Here, it sometimes makes sense to use a higher precision for the centre of the ball than the radius, such as the FloatMPDPBall class:

103 x0=Ball[FloatMP,FloatDP](q_(1/2),precision(bits=192))
107 xs=compute_iterates(f,x0,16)

If we only need approximate results with no guarantees on the accuracy, we can use an Approximation object, such as the FloatDPApproximation class:

108 x0=Approximation[FloatDP](0.5,double_precision)
112 xs=compute_iterates(f,x0,16)
Note
To construct a raw FloatDP object, one must always supply the precision as an argument:
113 a=FloatDP(exact(3.625),double_precision)
Since all binary floating-point numbers are dyadic, only Python int, Integer, ExactDouble and Dyadic are possible numerical arguments. A Rational argument must be rounded, either upward, downward, or to_nearest representable value, also abbreviated up, down and near. Hence to compute an approximation to \(f(x)\), we would need the following code:
120 a=FloatDP(Rational(38,10),to_nearest,double_precision)
122 b=FloatDP(1,double_precision)
123 x=FloatDP(Dyadic(1/two),double_precision)
124 fx=mul(near,a,mul(near,x,sub(near,b,x)))
This is obviously clunky, but even more importantly, the result is based on rounded computation, so may be inaccurate! For simplicity, safety, and clarity, users should use the Bounds, Ball and Approximation class for floating-point computations.

Effective real arithmetic

Although the Bounds and Ball classes allow for arbitrary accuracy, the precision is specified a-priori, limiting future accuracy. Ariadne also provides a Real number class which allows computation to attain a given, specified accuracy.

We can compute an iterate of \(f\) using real number arithmetic:

125 x=Real(q_(3/5))
135 for i in range(8): x=f(x)

The result is stored as a symbolic formula, which can be computed to a given (metric) accuracy.

136 y=x.compute(Accuracy(bips=128))

The result is a ValidatedReal, which is an abstract class storing guaranteed bounds on a real number. These bounds can be extracted as dyadic numbers:

139 w=y.get()

or using a specified precision:

141 w=y.get(double_precision)
143 w=y.get(precision(bits=128))

One can also compute using an Effort parameter. Increasing the effort garantees convergence, but not at a given rate.

145 y=x.compute(Effort(2))

It is aso possible to specify computation using a given precision:

149 w=x.compute_using(precision(bits=128))

The Real number class is also the most appropriate to use in problem specifications where irrational numbers are required.

The Function module

The full code of this tutorial is given in the file python/tutorials/function_tutorial.py.

In this tutorial, we will study iterated dynamical systems of the form \(x_{n+1}=f(x_n)\) by studying the iterated maps \(f^n\).

Univariate functions

Consider the unimodal function \(f(x)=a x (b-x)\).

Since the function has a single argument, and returns a single result, it is a ScalarUnivariateFunction. Since it is exactly specified and can be evaluated arbitrarily accurately, it is Effective. Hence the Python class name is EffectiveScalarUnivariateFunction. (The C++ template class is Function<EffectiveTag,Real(Real)>.)

There are two main ways of defining \(f\). We show how to define \(f\) in terms of the identity function \(\mathrm{id}(x)=x\):

0 id=EffectiveScalarUnivariateFunction.coordinate()
31 a=dec_(3.712)
32 b=z_(1)
33 f=a*id*(b-id)

Alternatively, we can define \(f\) in terms of a variable \(x\). Using \(\lambda\)-calculus syntax \(f=\lambda{x}.ax(b-x)\) (in pure Python we would write lambda x : a*x*(b-x) ) we have:

34 x=RealVariable("x")
37 f=make_function(x,a*x*(b-x))

We can define iterates of the function using the compose method:

38 f2=compose(f,f)
41 f3=compose(f,f2)

Multivariate functions

Consider the real Ikeda map \(f(x,y)=(1+a(x\cos(t)-y\sin(t)),a(x\sin(t)+y\cos(t))\bigr)\) where \(t=b-c/(1+x^2+y^2)\). For parameter values \(a=0.7\), \(b=0.4\) and \(c=6\), the system is chaotic. Since the function has a two-element vector argument, and returns a two-element vector result, it is a VectorMultivariateFunction.

We first define the parameters:

42 a=dec_(0.7)
68 b=dec_(0.4)
69 c=6

Again, we can define the function in terms of the identity and coordinate functions:

70 id=EffectiveVectorMultivariateFunction.identity(2)
72 x=id[0]
73 y=id[1]
74 t=EffectiveScalarMultivariateFunction(b-c/(1+sqr(x)+sqr(y)))
75 f=EffectiveVectorMultivariateFunction([1+a*(x*cos(t)-y*sin(t)),a*(x*sin(t)+y*cos(t))])

or in terms of variables:

76 x=RealVariable("x")
83 y=RealVariable("y")
84 t=b-c/(1+x*x+y*y)
85 f=make_function([x,y],[1+a*(x*cos(t)-y*sin(t)), a*(x*sin(t)+y*cos(t))])

Again, we can compute iterates of the function:

86 f2=compose(f,f)

and compute partial derivatives with respect to the components:

88 df0dx1=derivative(f[0],1)

We can evaluate the entire Jacobian derivative matrix at a point

89 jfx=jacobian(f,x)

Alternatively, we can compute all derivatives up to a given degree

104 ddfx=differential(f,x,2)

Function models

When computing operations which return functions, we usually can only compute over a bounded domain, and obtain an approximation, such as by a polynomial, together with some error bound. A concrete approximation over a bounded domain is called a FunctionModel in Ariadne, and is a ValidatedFunctionModel if an error bound is given. The domain of the approximation must be a bounded set, which we take to be an IntervalDomainType in the case of Univariate functions, and a coordinate-aligned BoxDomainType in the case of Multivariate functions. The floating-point types used for the precision of the coefficients and the error bound are also specified in the class signature. Hence a Taylor polynomial approximation with uniform error bound to a vector-valued multivariate function over a box using double-precision numbers for the coefficients and error bound is a ValidatedVectorMultivariateTaylorFunctionModelDP.

We first define the domain of definition of the function model:

107 dom=BoxDomainType([[x_(-0.25),x_(0.25)],[0,x_(0.5)]])
Note
The non-integer numbers must be prefixed with the modifier dy_, which indicates that the written values should be interpreted exactly as dyadic numbers. It is an error to use a non-dyadic number. The requirement that the bounds of the domain type must be exact dyadic numbers may be dropped in a future release of Ariadne.

To control the accuracy of the approximation, we use a Sweeper class. A general-purpose sweeper is the threshold sweeper ThresholdSweeper, which discards terms of the polynomial if they fall below a certain threshold.

113 swp=ThresholdSweeper[FloatDP](dp,1e-3)

We can then compute a polynomial approximation to the original function.

114 p=ValidatedVectorMultivariateTaylorFunctionModelDP(dom,f,swp)

The usual operations can be performed on function models, including composition

115 fp=compose(f,p)

and evaluation

118 x=Vector[Bounds[FloatDP]]([dec_(0.1),dec_(0.2)],dp)
120 px=p(x)

Here, the floating-point type used for the argument must match that used for the function model coefficients.

Additionally, function models can be integrated with respect to any of their variables

121 If0x1=antiderivative(p[0],1)

Solving Algebraic Equations

In this tutorial, we'll look at solving some simple algebraic equations, including parametrised equations.

The full code of this tutorial is given in the file python/tutorials/algebraic_equation_tutorial.py.

Computing roots and fixed-points

First, we will make a function and compute its fixed points

0 x=RealVariable("x")
29 f=make_function([x],[x**3+x/3])

To compute a fixed-point of \(f\), we need to solve the equation \(f(x)-x=0\). We define a new function \(g\) given by \(g(x)=f(x)-x\).

30 g=make_function([x],[(x**3+x/3)-x])

Note that currently, Ariadne only directly supports computing roots of multivalued functions \(g:\R^n\to\R^n\), so for a univariate function, we need to define it on one-element vectors, so \(g:\R^1\to\R^1\).

Since \(f(1/2)=7/24<1/2\) and \(f(1)=4/3>1\), by the intermediate value theorem, \(f\) has a fixed-point in \([1/2\!:\!1]\) We use this as the search region.

34 region=BoxDomainType([ [x_(0.5),x_(1)] ])
38 region=BoxDomainType([ [pr_(0.5),pr_(1)] ])
Warning
Currently, the search region is defined by an exact double-precision box. This means that the bounds must be given by exact integer, double-precision or dyadic numbers. To indicate that the user is aware of possible inaccuracies caused by use of the Python float class, floating-point numbers should be wrapped in a checker function x_() if the value is exact or pr_() if the written value can be interpreted as the nearest representable Python float. See the Extended numeric literals section for more details.

Specifiy the accuracy required of the solver, and provide a maximum number of iteration steps to use to prevent infinite loops.

40 tolerance=1e-9
45 max_steps=32

In Ariadne, algebraic equations are solved using a Solver class. A basic, but accurate and efficient solver is the IntervalNewtonSolver.

46 solver=IntervalNewtonSolver(tolerance,max_steps)
49 p=solver.solve(g,region)

Alternatively, we can use the related KrawczykSolver, which may be slightly more reliable, but less efficient.

51 solver=KrawczykSolver(tolerance,max_steps)
56 p=solver.solve(g,region)

Computing implicit and inverse functions

In this section,we will make a function and compute its inverse.

Declare variables and define the function \(f(x)=x^3+x/3\):

58 x=RealVariable("x")
66 y=RealVariable("y")
67 f=make_function([x],[x**3+x/3])

A function \(h\) is an inverse of \(f\) in a domain \(D\) if \(f(h(x))=x\) for all \(x \in D\). To compute the inverse, define the function \(g(x,y)=f(y)-x\), and solve the implicit function problem \(g(x,h(x))=0\).

68 x=RealVariable("x")
73 g=make_function([x,y],[(y**3+y/3)-x])

Look for the inverse over the interval \([0\!:\!1]\). Since f is increasing, \(f(0)=0\) and \(f(1)=4/3>1\), the inverse maps \([0:1]\) into \([0:1]\).

74 domain=BoxDomainType([[0,1]])
80 codomain=BoxDomainType([[0,1]])

Again, define the solver parameters. This time, we choose the slightly more robust KrawczykSolver for the problem.

81 tolerance=1e-6
83 max_steps=32
84 solver=KrawczykSolver(tolerance,max_steps)

Try to compute the inverse over \([0\!:\!1]\):

85 try:
89 invf=solver.implicit(g,domain,codomain)
90 print("invf:",invf)

Unfortunately, the interval Newton solver does not converge and yields an exception:

91 except:
92 print("Caught exception (method does not converge over domain ",domain,")",sep='')

Instead, look for inverse over smaller domains whose union is \([0\!:\!1]\):

93 domains=[BoxDomainType([[x_(0.0),x_(0.125)]]),BoxDomainType([[x_(0.125),x_(0.375)]]),BoxDomainType([[x_(0.375),x_(1.0)]])]
97 codomains=[BoxDomainType([[x_(-0.125),x_(0.5)]]),BoxDomainType([[x_(0.0),x_(0.75)]]),BoxDomainType([[x_(0.25),x_(1.25)]])]
98 for i in range(3):
100 invf=solver.implicit(g,domains[i],codomains[i])
101 print("invf",i,": ",invf,sep='')

The IntervalNewtonSolver is rather more sensitive, but we can still compute the inverse given sufficiently tight bounds:

102 newton_solver=IntervalNewtonSolver(tolerance,max_steps)
109 domain=BoxDomainType([[dy_(0.125),dy_(0.375)]])
110 codomain=BoxDomainType([[dy_(0.25),dy_(0.625)]])
111 invf=newton_solver.implicit(g,domain,codomain)
112 print("invf:",invf)
