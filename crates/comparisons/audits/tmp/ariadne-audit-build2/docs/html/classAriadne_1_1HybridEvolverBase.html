#include <hybrid_evolver.hpp>

Description

Base routines for hybrid evolution. Includes routines for extracting system information in a mode, applying initial events, computing crossing times, computing the evolution time, and applying a time step.

See also
The Hybrid Evolution Methods page for details of the basic algorithm.

NOTE: This class currently contains both a skeleton for hybrid evolution, and default implementations of many of the routines. It would be cleaner to have an interface class without these default implementations. However, which operations are needed may depend on the higher-level operations involved, so these methods should also not go in the interface.

Compute data on how trajectories of the flow cross the given guards. For example, trajectories may have a crossing where the guard value is strictly increasing which has a crossing_time as a function of the initial state.

The dynamic is given explicitly to facilitate computation of crossing times. A crossing_time computed must be valid over the initial_set, though will often be computed over the entire bounding box.

If the crossing is CrossingKind::INCREASING, then the crossing_time \(\gamma\) should be computed, satisfying \(g(\phi(x,\gamma(x)))=0\). If the crossing is CrossingKind::CONCAVE, the the critical_time (maximum_time) \(\mu\) should be computed, satisfying \(L_{f}g(\phi(x,\mu(x)))=0\).

Compute data related to the time of evolution related to the maximum time step allowed by the flow, the event times, and the final time which should be attained at the end of the evolution.

Postcondition
If the step_kind is SPACETIME_DEPENDENT_EVOLUTION_TIME, then the evolution_time must evaluate a value in [0,h] over the initial_set, where \(h\) is the step_size. In other words, \(\varepsilon(\xi(s),\tau(s))\in[0,h]\) whenever \(s\) is a valid parameter. If the step_kind is PARAMETER_DEPENDENT_FINISHING_TIME, then \((\omega(s)-\tau(s))\in[0,h]\) whenever \(s\) is a valid parameter. If the step_kind is CONSTANT_FINISHING_TIME, then \(t_{\max}-\tau(s)\leq h\) whenever \(s\) is a valid parameter.

Process the starting_set to find any immediately active events, and compute the relevant jump sets and the flowable or progress set.

First, and invariants \(i_e(x)\leq0\) are processed to give an allowable or invariant \(I=\{ x\in S \mid \forall e\in E_{\mathrm{inv}},\ i_e(x)\leq0\}\). Then for each urgent or permissive transition, the active set \(A_e = \{ x\in I \mid g_e(x)\geq 0\}\) and jump set \( _e = r_e(A_e)\) are computed. Finally, any progress predicates \(p_e(x)\leq0\) are processed (including those derived from urgent events), to give the flowable set \(P=\{ x\in I \mid \forall e\in E_{\mathrm{tcp}},\ p_e(x)\leq0\}\).

Apply guard_function for event to each set in sets, using the computed crossing_data.

The sets are updated with the extra constraints in-place for efficiency. In the case of a concave tangency, it may be necessary to split the enclosure in two, one part containing points which eventually cross the guard, the other points which miss the guard. The extra sets are adjoined to the end of the list of sets to be constrained. NOTE: The evolve_time should probably be in crossing_data, and should not really be necessary.
