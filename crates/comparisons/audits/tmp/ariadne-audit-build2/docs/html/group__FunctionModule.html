Function Module
Core Modules

Description

Functions on Euclidean space, including the Function<P,SIG> generic template class.

For the mathematical theory of computable functional analysis, see the Functional Analysis Page.

In this module are the classes used to represent concrete functions in Euclidean space. These functions can be used as the building blocks for geometric objects and dynamic systems.

The main Function<P,SIG> class represents continuous functions. Since any continuous function \(\R^n\to\R\) can be approximated arbitarily accurately be a polynomial function on a bounded domain, functions can compute polynomial approximations by application to a TaylorModel.

Function information tag.

The information tag (computational paradigm) P describes whether the function is exact, effective, validated or approximate. (See the InformationModule for more information.) Type aliases are provided, so EffectiveFunction<SIG> is an alias for Function<EffectiveTag,SIG>.

An effective function can be evaluated arbitrarily accurately given arbitrarily accurate approximations to the input. Hence if \(f\) is a EffectiveFunction, then it can be automatically converted to a ValidatedFunction.

Function signatures

The signature SIG takes the form RES(ARGS...) where RES describes the output and ARGS... the input. Hence a signature Real(Real) indicates a function \(\R\to\R\), whereas RealVector(RealVector,Real) would indicate a function \(\R^n\times\R\to\R^m\).

Remarks
Currently, only Real and RealVector are supported types for use in RES and ARGS, with RealScalar a synonym for Real.

template<class X, class A>
ArithmeticType< X, A > horner_evaluate ( const Expansion< MultiIndex, X > & e,
const Vector< A > & x )

Evaluate a power series on an algebra using Horner's rule.

For a polynomial in \(n\) variables, Horner's rule is a recursive formula

\[ p(x) = \bigl( \bigl( x^{d_k-d_{k-1}} q_k(\hat{x})x^{d_0} + \cdots + q_1(\hat{x}) \bigr) x^{d_1-d_0} + q_0(\hat{x}) \bigr) x^{d_0} \]

where \(\hat{x}=(x_1,\ldots,x_{n-1})\) and \(q_i\) is the polynomial of terms in \(x_n^{d_i}\). To evaluate a polynomial using Horner's rule without using recursive function calls, we maintain registers \(r_k\) containing the current evaluation of a polynomial in \((x_1,\ldots,x_k)\).

We list the terms in reverse lexicographic order, defined as \(\alpha \prec \beta\) if \(\alpha_j>\beta_j\), where \(j=\max\{i\mid \alpha_i\neq\beta_i\}\). For a given term \(c_\alpha x^\alpha\), let \(k=\max\{j\mid \alpha_j\neq\beta_j\}\), where \(\beta\) is the next multi-index. We update register \(r_k\) by

\[r'_k=(((c_\alpha + r_1) x^{\alpha_1} + r_2 )x^{\alpha_2}+\cdots r_k)x^{\alpha_k-\beta_k}.\]

The result is obtained by updating a fictional register \(r_{n+1}\) at the last step. See J. M. Pena and T. Sauer, "On the multivariate Horner scheme", SIAM J. Numer. Anal. 37(4) 1186-1197, 2000.
