Mathematical Definition of a Hybrid Automaton

A traditional mathematical definition of a hybrid automaton is as follows:

A hybrid automaton is a tuple \(H=(Q,E,\gamma,n_q,f_q,I_q,r_{q,e},G_{q,e})\) where

  • The discrete behaviour is
    • \(Q\) is a finite set of discrete states
    • \(E\) is a finite set of discrete events
    • \(\gamma:\subset Q\times E\rightarrow Q\) is a partial function giving the discrete transitions
  • For each \(q\in Q\),
    • \(n_q\) defines the dimension of the continuous state space \(\R^{n_q}\).
    • \(f_q:\R^{n_q}\rightarrow \R^{n_q}\) defines the continuous dynamics by \(\dot{x}=f_q(x)\).
    • \(I_q\subset \R^{n_q}\) is the invariant which must hold throughout the evolution in mode \(q\).
  • For each \((q,e)\in\mathrm{dom}(\gamma)\subset Q\times E\),
    • \(r_{q,e}:\R^{n_q}\rightarrow \R^{n_\gamma(q,e)}\) defines the reset by \(x'=r_{q,e}(x)\).
    • \(G_{q,e}\subset \R^{n_q}\) is the guard which must hold for event \(e\) to be possible.

The standard operational semantics of a hybrid automaton \(H\) is as follows.

  • The state of the system is a pair \((q,x)\) with \(q\in Q\) and \(x\in\R^{n_q}\).
  • The state may evolve according to the differential equation \(\dot{x}=f_q(x)\) as long as \(x\in I_q\).
  • The state may evolve according to the discrete transition \((q',x')=(\gamma(q,e),r_{q,e}(x))\) as long as \(x\in R_{q,e}\).

This definition has some disadvantages:

  1. The main disadvantage concerns the modelling of urgent transitions. These are transitions which occur as soon as the guard set is entered, for example, as soon as \(g(x)\geq0\). The traditional way of modelling these transitions is to introduce the constraint \(g(x)\leq 0\) into the invariant. However, the condition that the event occurs exactly when \(g(x)=0\) is lost, and this is often very useful in computing the evolution.
  2. The invariant and guards in a mode determining the coupling between continuous and discrete dynamics. During the evolution, we usually need to consider both simultaneously. For this reason, it is preferable to consider invariant and guard sets at the same level.
  3. An invariant may prevent a transition from occurring by being violated in the new state. This entails some "look-ahead" in the definition of the evolution. Some systems e.g. CIF introduce "progress predicates" to prevent continuous evolution without preventing a jump into the point.
  4. There is no "concrete" format for sets. Although this is not strictly necessary, many numerical operations can be efficiently computed on sets defined by inequality constraints \(c(x)\leq 0\) and equality constraints \(e(x)=0\).

More generally, there are many different ways of specifying when continuous evolution is allowed, and when discrete transitions are allowed.

  • Invariant/Guard Set: Continuous evolution allowed when \(x\in I_q\); discrete transtions allowed when \(x\in G_{q,e}\).

The Ariadne Hybrid Automaton Data Type (Version 0.4)

The hybrid automaton interface in Ariadne is essentially equivalent to the enhanced mathematical definition given above. The dynamic and resets are defined using the VectorFunction class. The guards and invariants are defined using the class ScalarFunction class, with invariants \(i(x)\leq0\) and guards \(g(x)\geq0\). A DiscreteMode is a triple \((q,f_q,I_q)\) where

  • \(q\) is a DiscreteState.
  • \(f_q\) is a VectorFunction giving the dynamic \(\dot{x}=f_q(x)\).
  • \(I_q\) is a List of ScalarFunction with each \(i_j:\R^{n_q}\rightarrow \R\) giving the invariants \(i_j(x)\lesssim 0\).

A DiscreteTransition is a triple \((e,s,t,r,g,u)\) where

  • \(e\) is a DiscreteEvent.
  • \(s\) and \(t\) are the source and target DiscreteState.
  • \(r:\R^{n_s}\rightarrow\R^{n_t}\) is a VectorFunction giving the reset \(x'=r(x)\).
  • \(g:\R^{n_s}\rightarrow\R\) is a ScalarFunction giving the guard \(g(x)\gtrsim 0\).
  • \(u\in\{\top,\bot\}\) is a flag determining whether the transition is urgent or not.

A HybridAutomaton is a pair \((M,T)\) where

  • \(M\) is a set of discrete modes, and
  • \(T\) is a set of discrete transitions such that
    • for every transition, the source \(s\) and target \(t\) correspond to modes in \(M\), and
    • for every event \(e\), there is at most one transition with a given source \(s\).

The Ariadne Hybrid Automaton Framework

A Mode is a tuple \((q,f_q)\) where

  • \(q\) is a DiscreteLocation.
  • \(f_q\) is a VectorFunction giving the dynamic \(\dot{x}=f_q(x)\).

A Guard is a tuple \((q,e,c,k)\) where

  • \(q\) is a DiscreteLocation.
  • \(e\in E\) is an Event label.
  • \(c:\R^{n_s}\rightarrow\R^{n_t}\) is a ScalarFunction giving the condition \(c(x)\geq0\).
  • \(k\in K\) determines the action to be taken when \(c(x)\geq 0\) is satisfied. For example, in an urgent event, the transition corresponding to event \(e\) in location \(q\) must be taken as soon as the condition is satisfied, whereas for an invariant, the evolution is terminated (unless a transition corresponding to another event is activated.

A Transition is a tuple \((s,e,t,r)\) where

  • \(s\) is the source DiscreteLocation.
  • \(e\) is the DiscreteEvent.
  • \(t\) is the target DiscreteLocation.
  • \(r:\R^{n_s}\rightarrow\R^{n_t}\) is a VectorFunction giving the guard \(g(x)\gtrsim 0\).

The Ariadne Interface for Hybrid Systems

So that the evolution routines in Ariadne are independent of the class of hybrid system used, all hybrid systems need to correspond to the HybridAutomatonInterface, which specifies a minimal set of operators which the system must provide.

A hybrid automaton is defined by the data

\[ \bigl( Q, E, \{ n_q, f_q \mid q\in Q\}, \{ c_{q,e},k_{q,e} \} , \{t_{q,a},r_{q,a}\} \bigr) \]

where

  • \(n_{q}\in \N\) is the dimension of the continuous state space in location \(q\).
  • \(f_{q}:\R^{n_q}\rightarrow\R^{n_q}\) defines the continuous dynamics \(\dot{x}=f(x)\) in location \(q\).
  • \(c_{q,e}:\R^{n_q}\rightarrow \R\) defines the activation condition \(c_{q,e}(x)\geq0\) for the event \(e\) in location \(q\).
  • \(k_{q,e}\) is the kind of the event \(e\) in location \(q\).
  • \(t_{q,e}\in Q\) is the target of the transition \(a\) in location \(q\).
  • \(r_{q,e}:\R^{n_q}\rightarrow\R^{n_{t_{q,e}}}\) is the reset map for the transition \(a\) in location \(q\).

Additionally, we provide the data \(G_q\) defining a "grid" in location \(q\).

Possible future extensions:

  • Extend the range of continuous dynamics beyond vector fields \(\dot{x}=f(x)\) to allow more general systems e.g. explicit flows \(x(t)=\phi(x_0,t-t_0)\) or differential inclusions \(\dot{x}(t) = f(x(t),v(t));\ v(t)\in V\).
  • Extend the range of discrete dynamics beyond continuous maps e.g. multivalued maps \(x' \in \{ r(x,w) \mid w\in W\}\).
  • Extend the activation conditions to allow non-smooth functions or logical predicates. e.g. \(\min(c_1(x),c_2(x)) \geq 0\) or \(c_1(x)\geq 0\wedge c_2(x)\geq 0\).

Glossary of Terms describing Hybrid Systems

There are many terms used to describe features of a hybrid system in the literature. However, the precise use of these terms is non-standard. In order to fix the terminology used in Ariadne, we use the following definitions. Some of these definitions may be different from what is "common" in the literature; this will usually be due to internal considerations (e.g. labelling), or the fact that existing frameworks typically do not consider computability issues, and hence blur concepts which should be kept separate.

  • (Discrete) Event: A label for any behaviour of the system other than continuous evolution.
    • Action: An event causing a change in the state of the system.
  • (Discrete) Location: A value of the discrete state of the system.
  • (Discrete) Mode: The specification of the (continuous) behaviour in a discrete location.
  • Condition: A predicate \(X\fto \{\top,\bot\}\) determining when an event is active. Typically defined using a constraint function \(c:X\rightarrow\R\) as \(c(x)\geq0\); may also be defined as \(x\in C\) for some set \(C\).
    • Invariant Condition: A predicate \(\mathrm{inv}_q(x)\) which must hold at all states reached by the system evolution.
    • (Time-Can-)Progress Condition/Predicate: A predicate \(\mathrm{tcp}_q(x)\) which must hold whenever continuous evolution is possible. Given by a function \(p_{q,e}(x)\leq0\)
    • Guard Condition: A condition \(\mathrm{act}_q(x)\), usually given by a function \(g_{q,e}(x)\geq0\), such that the event e only occurs when the condition is satisfied.
      • Urgent Guard: A condition \(\mathrm{act}_q(x)\), usually given by a function \(g_{q,e}(x)\geq0\) which implies that event e occurs as soon as the condition is satisfied. Formally equivalent to introducing the progress predicate \(g_{q,e}(x)\leq0\).
      • Permissive Guard: A condition \(\mathrm{act}_q(x)\), usually given by a function \(g_{q,e}(x)\geq0\) which implies that event e occurs as soon as the condition is satisfied. Note that if another event is also possible, then although an event must occcur, both the event with the urgent guard and the other event may occur.
    • Activation Condition: A synonym for a permissive guard.
  • Active: An event is active when its constraint condition is satisfied.
  • Update: A rule governing how the state changes upon an event. For a given source location, comprises a target location and reset map.
    • Target: The location forming the discrete state after a transition.
    • Reset: A function mapping continuous states in the source location to continuous states in the target location upon a discrete transition.
