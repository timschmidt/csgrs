Python Interface

The Python interface provides Python bindings to Ariadne's C++ library. It does not introduce new functionality; instead it merely makes the C++ classes, methods, functions and variables usable from a Python script.

As far as possible, the Python interface mimics the C++ interface, so the C++ documentation is also applicable for Python users. However, there are some unavoidable differences, due to the differences between C++ and Python. The main differences that Python users consulting the C++ documentation should be aware of are given below:

  • Not all classes and methods are exported:
    To see which classes are exported, type:
    python3 -c "import ariadne; print(dir(ariadne))"
    Missing classes may be added in a future release.
  • C++ templates:
    C++ allows classes to be defined which depend on other classes; such classes are called templates. For example, the template Bounds<X> describes bounds on a quantity, where the lower and upper bounds are objects of class X. Thus Bounds<Dyadic> represents dyadic bounds on a real number, and Bounds<FloatMP> would represents multiple-precision floating-point bounds. Each instantiation of a C++ template yields a different class.
    Since Python does not have templates, in the Python interface, each instantiation is a separate class. The class name is derived from the template name and the class parameter. For example, Bounds<Dyadic> translates to the Python class DyadicBounds. The Python class name is available from C++ (and can be found in the documentation) as a C++ typedef class alias.
    For some C++ templates, the C++ class T<X> is avalable in Python as T[X]. For example, the C++ template class Float<DP>, with Python class name FloatDP, is also available in Python as Float[DP], and the C++ template class Bounds<Float<DP>> with python class name FloatDPBounds, is also available in Python as Bounds[Float[DP]] or Bounds[FloatDP].
  • Conversion:
    Conversions from a class F to a class T are defined by a constructor T(F) in class T, or by a conversion operator operator T() in class F. Such conversions may be automatically applied in the Python interface when dispatching functions, though the conversion applied may differ slighly from the C++ version. When in doubt, use an explicit constructor T(obj) to convert to type T.
  • Operators:
    In both C++ and Python, unary and binary mathematical operators represented by a symbol ★ can be defined, and are used by ★x or x1★x2. e.g. the addition operator is used by x1+x2. In Python, operators are defined by specially-named class methods. e.g. addition is defined by the add method. In C++, the operator ★ is defined by the function with name operator★. e.g. addition is defined by operator+(X1 x1, X2 x2). To find the information about a Python operator with symbol ★, you should look for operator★ in the C++ API docmentation.
    Note that C++ does not have a 'power' operator; operator^ is 'bitwise exclusive or', and has a lower precedence than multiplication. In Python, the power operator is used by x1 ** x2.
    Since Python does not allow user-defined logical operations and, or and not, these are implemented by the 'bitwise' operators &, | and ~, and are used by b1&b2, b1|b2 and ~b2.
  • Printing:
    In C++, printing is achieved by defining OutputStream& operator<<(OutputStream& os, Class obj). In Python, printing is performed by the print(obj) statement, or by converting to a string using str(obj) or repr(obj). The Python output of repr typically differs from the C++ output or that of str, and is designed so that eval(repr(obj)) yields an object equivalent to the original argument.
  • C++ extended literals:
    The C++ operator"" can be used to define extended numeric and string literals. For example, operator""_dy(long long double) can be used as 1.375_dy to be interpreted as the Dyadic number \(11/2^3\). Python does not support extended literals, but the same result may be obtained either by a constructor, or by using the literal tag as a function e.g. dy_(1.375).
