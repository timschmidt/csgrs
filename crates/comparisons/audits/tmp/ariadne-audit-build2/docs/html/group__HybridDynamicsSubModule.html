◆ CrossingKind

enum class CrossingKind : std::uint8_t
strong

The way trajectories of the flow \(\phi(x_0,t)\) of \(\frac{dx}{dt}=f(x)\) cross the guard set \(g(x)=0\). The rate of change of the guard function changes along flow lines is given by \(d g(x(t))/dt = L_{f}g(x(t))\) where the Lie derivative \(L_{f}g\) is defined by \(L_{f}g(x) = (\nabla g\cdot f)(x)\).

Defaults to DEGENERATE whenever the crossing kind has not been resolved; this need not necessarily mean that the crossing is degenerate, but may also imply that the crossing information is too expensive or sensitive to compute.

Enumerator
DEGENERATE 

The crossing may be degenerate to second order.

NEGATIVE 

The guard function is negative on the flow domain. No event occurs.

POSITIVE 

The guard function is negative on the domain. The event occurs immediately (if urgent) or at all times (if permissive).

MONOTONE 

The guard function is strictly increasing or decreasing along flow lines at a crossing point. i.e. \(\frac{d}{dt}g(\phi(x_0,t))>0\) whenever \(g(\phi(x_0,t))=0\). Implied by \(L_{f}g \geq 0\).

INCREASING 

The guard function is strictly increasing along flow lines at a crossing point. i.e. \(\frac{d}{dt}g(\phi(x_0,t))>0\) whenever \(g(\phi(x_0,t))=0\). Implied by \(L_{f}g \geq 0\).

DECREASING 

The guard function is strictly decreasing along flow lines.

CONCAVE 

The guard function is positive over at most an interval. Implied by concavity along flow lines, which is equivalent to \(L_{f}^{2} g < 0\) within the reached set.

CONVEX 

The guard function is negative over at most an interval. Implied by convexity along flow lines. Implied by convexity along flow lines, which is equivalent to \(L_{f}^{2} g > 0\) within the reached set.

TRANSVERSE 

The guard function is strictly increasing along flow lines, and the crossing time can be computed as a smooth function of the initial state. Given an initial point \(x_0\), the crossing time is \(\gamma(x_0)\).

GRAZING 

The time at which the guard function reaches a maximum along flow lines is a smooth function \(\mu(x_0)\) of the initial state \(x_0\). Implies by concavity along flow lines, which is equivalent to \(L_{f}^{2} g < 0\) within the reached set.

◆ StepKind

enum class StepKind : std::uint8_t
strong

The kind of step taken in the evolution. Determines how the evolution time is specified.

Assumes that the starting set and time is given as a subset of \(\{ \xi(s); \tau(s) \mid s\in D\}\) where \(s\in D\) is a parameter, \(x=\xi(s)\) is the state corresponding to parameter \(s\), and \(t=\tau(s)\) is the time the point has so far been evolved for. Assumes that the flow is given by a function \(x'=\phi(x,t)\), typically only defined over a bounded set of space and time.

See also
TimingData
Enumerator
CONSTANT_EVOLUTION_TIME 

The step is taken for a fixed time \(h\). The actual step length depends only on the starting state. After the step, we have \(\xi'(s) = \phi(\xi(s),h)\) and \(\tau'(s)=\tau(s)+h\).

SPACE_DEPENDENT_EVOLUTION_TIME 

The step is taken for a time \(\varepsilon(x)\) depending only on the starting state. After the step, we have \(\xi'(s) = \phi(\xi(s),\varepsilon(\xi(s)))\) and \(\tau'(s)=\tau(s)+\varepsilon(\xi(s))\).

TIME_DEPENDENT_EVOLUTION_TIME 

The step is taken for a time \(\varepsilon(t)\) depending only on the starting time. After the step, we have \(\xi'(s) = \phi(\xi(s),\varepsilon(\tau(s)))\) and \(\tau'(s)=\tau(s)+\varepsilon(\tau(s))\).

SPACETIME_DEPENDENT_EVOLUTION_TIME 

The step is taken for a time \(\varepsilon(x,t)\) depending only on the current state (space and time). After the step, we have \(\xi'(s) = \phi(\xi(s),\varepsilon(\xi(s),\tau(s)))\) and \(\tau'(s)=\tau(s)+\varepsilon(\xi(s),\tau(s))\).

PARAMETER_DEPENDENT_EVOLUTION_TIME 

The step is taken for a time \(\delta(s)\) depending on the parameterisation of the set. After the step, we have \(\xi'(s) = \phi(\xi(s),\delta(s))\) and \(\tau'(s)=\tau(s)+\delta(s)\).

PARAMETER_DEPENDENT_FINISHING_TIME 

The step is taken up to a time \(\omega(s)\) depending on the parameterisation of the starting set. After the step, we have \(\xi'(s) = \phi(\xi(s),\omega(s)-\tau(s))\) and \(\tau'(s)=\omega(s)\).

SPACETIME_DEPENDENT_FINISHING_TIME 

The step is taken up to a time \(\omega(x,t)\) depending only on the current state (space and time). After the step, we have \(\xi'(s) = \phi(\xi(s),\omega(\xi(s),\tau(s)-\tau(s)))\) and \(\tau'(s)=\omega(\xi(s),\tau(s))\).

CONSTANT_FINISHING_TIME 

The step is taken up to the specified evolution time \(t_{\max}\). The actual step length depends on the parameterisation. After the step, we have \(\xi'(s) = \phi(\xi(s),t_{\max}-\tau(s))\) and \(\tau'(s)=t_{\max}\).

◆ FinishingKind

enum class FinishingKind : std::uint8_t
strong

The way in which the step interacts with the final evolution time.

Used to control whether final time constraints need to be added, whether further evolution is possible, and whether and how sets should be put in the list of final sets. Needed since the final time may be an arbitrary real number, at it may not be possible to determine whether a given enclosure is exactly at the final time or not

See also
TimingData
Enumerator
BEFORE_FINAL_TIME 

At the end of the step, the final time has definitely not been reached by any point.

AT_FINAL_TIME 

At the end of the step, the final time is reached exactly. No more evolution is possible.

AFTER_FINAL_TIME 

At the end of the step, the final time has definitely been passed by every point. No more evolution is possible.

STRADDLE_FINAL_TIME 

At the end of the step, some points may have passed the final time, and some may not reached it. Usable as a default value.
