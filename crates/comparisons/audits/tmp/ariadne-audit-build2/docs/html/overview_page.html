Reachability Analysis of Hybrid Systems

The main functionality of Ariadne is to perform reachability analysis and verification of hybrid systems. A hybrid system is a dynamic system in which continuous evolution is interspersed with discrete jumps. The state space of a hybrid system is of the form \(X=\bigcup_{q\in Q} \{q\}\times \R^{n_q}\) with \(Q\) a finite set of locations. The evolution of a hybrid system proceeds via a differential equation \(\dot{x}(t) = f_q(x(t))\) in location \(q\) until a guard condition \(g_e(x)\geq 0\) is satisfied, in which case the event \(e\) occurs, the location jumps to a target location \(q'=\tau(q,e)\) and the continuous state jumps to \(x'=r_{q,e}(x)\).

A trajectory or execution of a hybrid system comprises continuous evolution interspersed with discrete events. We let \(t_0\) be the starting time (canonically \(t_0=0\)) and \(t_n\) the time when the \(n^\mathrm{th}\) event \(e_n\) occurs. Since more than one event may occur at the same time, we keep track of both the total number of events as well as the elapsed time when describing a trajectory. A trajectory is therefore a partial function \(\xi(t,n)\) defined whenever \(t_n\leq t\leq t_{n+1}\). The domain of \(\xi\) is a hybrid time domain \(T=\{ (t,n)\in\R^+\times\Z^+ \mid t\in[t_n,t_{n+1}]\). A trajectory is Zeno if the total number of event \(N\) equals \(\infty\), and \(\lim_{n\to\infty} t_n < \infty\).

In reachability analysis we are given an initial set \(X_0 \subset X\), and aim to compute the set of points which are reachable by a trajectory starting in \(x_0\). The reachability analysis may be performed over a finite time interval, in which case a bound on the total time \(T\) and the maximum number of events \(N\) is given, or over an infinite time interval.

In both cases, we can compute either an over-approximation to the reachable set \(R\), or a lower approximation. A set \(A\) is said to be an \(\epsilon\)-lower approximation to \(S\) if \(A\subset N_\epsilon(S)\), and an over-approximation if \(A\supset S\). For general systems it is impossible to compute a sequence of over-approximations converging to the infinite-time reachable set. Instead, we compute over-approximations to the reachable set which converge to the chain-reachable set as the accuracy parameters governing the computation are improved.

Function Calculus

The computational kernel of Ariadne is based on a calculus of continuous functions on Euclidean space. The core type is of (multivariable, vector-valued) functions \(f:\R^n\rightarrow\R^m\). These functions can be built from scalar-valued functions \(\R^n\rightarrow\R\) componentwise, starting from the constant functions \(f(x_1,\ldots,x_n)=c\), the coordinate projection functions \(f(x_1,\ldots,x_n)=x_i\), arithmetical operations \(+,-,\times,\div\), the absolute value operation \(|x|\) and simple functions such as \(\mathrm{sqrt}\), \(\exp\), \(\log\) and \(\sin\).

The results of operations on functions are expressed in terms of interval functions on bounded domains. An interval function is a map \(\mathbb{IF}^n\rightarrow\mathbb{IF}^m\) where \(\mathbb{IF}\) is the set of intervals in \(\R\) with endpoints in a subset \(\mathbb{F}\) of \(\R\). An interval function \(\hat{f}:\mathbb{IF}^n\rightarrow\mathbb{IF}^m\) is an interval extension of \(f:\R^n\rightarrow\R^m\) if for every box \(\ivl{x}=[a_1,b_1]\times\cdots\times[a_n,b_n]\in\mathbb{IF}^n\) and every \(x\in\ivl{x}\), we have \(f(x)\in \hat{f}(\ivl{x})\).

If the result of an exact operation is a continuous function \(f:U\fto\R^m\) where \(U\) is an open subset of \(\R^n\), then the computed solution is typically an interval function \(\hat{f}:\IF^n\fto\IF^m\) which is a valid interval extension of \(f\) on a box \(D\subset U\).

The main operations which Ariadne can perform are

  • Solution of differential equations: Given a differential equation of the form \(\dot{x}=f(x)\), computes the flow \(\phi(x,t)\) satisfying \(\phi(x,0)=x\) and \(\dot{\phi}(x,t) = f(\phi(x,t))\).
  • Solution of (parameterised) algebraic equations: Given an algebraic equation \(f(a,x)=0\), find a function \(h(a)\) satisfying \(f(a,h(a))=0\).
  • Nonlinear feasibility problems: Given a set of nonlinear constraints \(g_i(x)\in C_i\), determine whether there exists a solution with \(x\in D\).
  • Solution of nonlinear programming problems: Given a nonlinear programming problem \( \max f(x) \text{ such that } x\in D,\ g(x)\leq 0\text{ and } h(x) = 0 \) where \(D\) is a bounded domain, find all (local) solutions.

Main Classes

Ariadne comprises a number of modules, which may be roughly classifies into user modules, including core data types, system classes and analysis tools, and internal modules which are used by the kernel and which the average user need not be concerned about.

  • Main user classes for reachability analysis of hybrid systems.
    • System classes implementing HybridAutomatonInterface for defining hybrid systems,
    • Evolution classes implementing HybridEvolverInterface for computing the evolution of a hybrid system from a given initial set, and a HybridReachabilityAnalyser for performing global reachability analysis
    • Output classes Figure for plotting sets and orbits.
  • Auxiliary user classes, used to define systems and store output.
    • Numeric classes, including Real, Bounds<F> and Approximation<F> based on floating-point types FloatDP and FloatMP, and concrete Integer, Dyadic, Decimal and Rational classes.
    • Linear algebra classes, Vector<X> and Matrix<X> , templated on the numerical type.
    • Function classes, including the general Function type, with ScalarUnivariateFunction, VectorUnivariateFunction, ScalarMultivariateFunction and VectorMultivariateFunction, specific ConstantFunction, CoordinateFunction, Affine function, and Polynomial function types.
    • Geometric classes, including affine geometric types such as Point, Box and Polyhedron, and general ImageSet, ConstraintSet and ConstrainedImageSet objects, and generic sets such as OpenSet, OvertSet and CompactSet defined by abstract interfaces.
    • Storage class Orbit< S > for storing evolution traces and GridTreePaving for storing reached sets.
  • Internal classes, used in computations.
    • Automatic differentiation classes Differential<X> .
    • Differential calculus classes, including TaylorModel class for high-order polynomial approximation to dependent quantities.

Function patch models, such as the ScalarMultivariateTaylorFunctionModel and VectorMultivariateTaylorFunctionModel classes, for storing approximation to functions over bounded sets.

  • Evaluation classes for performing nontrivial internal computations.
    • Differential equation solvers satisfying the IntegratorInterface.
    • Algebraic equation solvers satisfying the SolverInterface.
    • Nonlinear programming classes satisfying the OptimiserInterface.
    • Constraint propagation classes satisfying the ConstraintSolverInterface.

Building a Hybrid System

In order to use Ariadne for reachability analysis, it is first necessary to build a hybrid system. The HybridAutomaton class is the main Ariadne class for describing hybrid systems as a single hybrid automaton. A MonolithicHybridAutomaton comprises DiscreteMode and DiscreteTransition objects to describe the modes (including continuous dynamics and invariants) and the discrete transitions (describing guards/activation predicates and reset relations.

An Ariadne automaton must be built explicitly using the new_mode , new_invariant and new_transition methods.

All resets, flows and guards are specified using functions. A function is just a mapping from \(\R^m\) to \(\R^n\). Unfortunately, since Ariadne uses specialised automatic differentiation functionality, an Ariadne function cannot be specified directly from a C++ function, but must be defined using the a function object. The ScalarFunction and VectorFunction classes can be used to build and represent simple functions. The ScalarUserFunction<F> and VectorUserFunction<F> can be used to wrap more complex user function objects to conform to the Ariadne interface.

Building an Evolver or Analyser

In order to analyse a hybrid system, we need an Evolver or Analyser class. An Evolver class is used to perform simulations, and computes the evolution up to a given time starting from an initial enclosure set. An Analyser class is used to perform global analysis, and computes the evolution starting from an arbitrary given set. Internally, an Analyser class typically uses an Evolver to perform the evolution, and then performs a discretization of the evolved set on a grid.

An evolver class satisfies the interface EvolverInterface<SYS,ES> , where ES is the template parameter giving the type used for the enclosure sets. The HybridEvolverInterface class is an interface for evolvers for hybrid systems using the type HybridEnclosure to specify the continuous part of the enclosure set. To build an Evolver class, we need to give evolution parameters to specify the accuracy of the computation. The evolution parameters are passed using the evolver's configuration class. Note that not all parameters need be used by a given Evolver class.

A reachability analyser class satisfies the interface ReachabilityAnalyserInterface<SYS> . The class HybridReachabilityAnalyser may be used to perform reachability analysis of hybrid systems. It can be constructed from a HybridEvolverInterface class.

Remarks
We use Evolver and Analyser classes rather than functions to perform the analysis since different methods require different user parameters to specify the accuracy.

A reachability analyser class satisfies the interface ReachabilityAnalyserInterface<SYS>. The class HybridReachabilityAnalyser may be used to perform reachability analysis of hybrid systems. It can be constructed from a HybridEvolverInterface class.

Performing Simulations or Reachability Analysis

The functionality available for computing (rigorous) simulations, and performing reachability analysis can be found in the documentation for EvolverInterface<SYS,ES> and ReachabilityAnalyserInterface<SYS> .
