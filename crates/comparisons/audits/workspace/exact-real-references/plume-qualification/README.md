## Benchmark interpretation

KernelProbe.bench-final.hs is the exact final probe source (SHA-256
878702fd8e48bff034532330a908a58b68b1bc0ebe751a05ff1a4751f3762762).
The final binary uses this source and the retained compatibility copy.
216 observations:two multiply paths, three input families, four demands,
nine rounds. Discard round0 as warmup:192 final observations, eight per group,
with four executions in each pair order. All are pinned to CPU6; CPU time is
reported in picoseconds, GHC cumulative managed allocation in bytes.

Inputs are equally pre-forced; fresh output prefixes are forced into integers.
Each batch has16 distinct rational operand pairs. Correctness checks occur
outside the timed region and use exact Rational arithmetic. This compares
within-GHC output kernels, not end-to-end input construction, wall-clock
throughput, retained RSS, or Hyper-versus-Haskell performance. Submillisecond
samples have limited timing resolution; allocation differences and larger
demand cases are more informative. The source and code-size simplification of
the dyadic implementation does not justify its substantially greater work.

No new production change is selected in this checkpoint. The remaining source
variants, report, and plausible transfers stay open in the root ledger.
