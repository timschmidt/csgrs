# DedekindCutArithmetic.jl audit notes

- Repository pin: `dc7a51b784a6d8f04be22fcca862656432a3d87e`.
- Complete inventory: 53 files (including CI, policy, docs, assets, source and tests); every file was enumerated and hashed in the companion inventory. Source, tests, and documentation were read in bounded numbered chunks; non-code configuration/policy files were classified by hash and role.
- Architecture: Julia 1.10+ package using dyadic endpoints (`BigInt` mantissa plus `Int64` exponent), Kaucher/generalized dyadic intervals, mutable cached Dedekind cuts, lazy unary/binary composite cuts, and quantifier search accelerated by ForwardDiff derivatives. `FunctionWrapper` erases predicate types.
- Exactness strengths: directed dyadic enclosure, lazy refinement, explicit overlap-driven comparisons, rational decimal parser, and generalized intervals. The abstract-Dedekind interface is a useful model for separating exact values from requested enclosure precision.
- Static correctness risks: `DyadicReal` division by zero throws `DomainError(d, ...)` with an undefined variable `d` (should identify the divisor); `RoundNearest` shifts by `e-1`, so an exponent-zero dyadic can trigger a negative shift; exponent arithmetic and interval precision calculations have no overflow guards. `DedekindCut` refinement mutates a shared cache without synchronization. Composite refinement refines both children symmetrically rather than allocating precision by conditioning/error contribution.
- Termination/completeness risks: comparisons and quantifiers refine until intervals separate, with no semantic undecidable/unknown result. Quantifier recursion can diverge on discontinuous predicates, equal-boundary predicates, or float literals that collapse to the same value. `max_iter` is only available on `refine!`, not on the public comparison/quantifier loops. Unbounded `ℝ` is replaced by finite `big(typemax(Int))`; `sqrt` assumes nonnegative input but has no explicit domain contract.
- Performance/memory: every refinement allocates new `BigInt`/interval values; mutable cache gives reuse but is not thread-safe. `FunctionWrapper` and ForwardDiff add dispatch/allocation overhead. No benchmark suite is supplied.
- Tests: package-native Julia tests could not run because MacroTools, FunctionWrappers, ForwardDiff, SafeTestsets and Aqua are absent and registry installation is blocked by the full filesystem quota. Static tests cover ordinary arithmetic but omit zero-divisor diagnostics, exponent-zero rounding, thread safety, overflow, boundary/nontermination and generalized interval multiplication combinations.
- Hyper transfer decision: no production change selected. The useful conceptual transfer is explicit refinement budgets/unknown outcomes and condition-aware precision scheduling, but Hyper already has stronger immutable DAGs, synchronized demand-driven caches, and explicit domain/error contracts. DedekindCutArithmetic's mutable cache, recursive unbounded search, finite fake infinity, dependency-heavy derivative heuristic, and identified bugs are not suitable for Hyper.
