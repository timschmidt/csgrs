# Finite conic subdivision: confirmed representation gap

V639 is reaped. Its public Curve2 probe confirms that the general rational carrier splits and accepts a second cut while the identical native rational quadratic fails. This is independent of the repaired pole-boundary case. Controls (0,0),(1,1),(2,0), weights 1,-1/2,1 give D(t)=1/4+3(t-1/2)^2. The cut t=2/3 is finite at (2,-2/3). Its left homogeneous control net contains (-1/3,-1/3,0), so an affine middle control does not exist although the entire curve is finite.

Owning restriction: RationalQuadraticBezier2::subcurve_between_exact and ::split_at_exact return only RationalQuadraticBezier2. Their private rational_from_homogeneous rejects every zero control weight, including an interior control. Curve2::subcurve_with_policy, BezierSubcurve2::subcurve_between_exact, native split materialization and retained overlap materialization preserve that narrow result type. The general RationalBezier2::from_homogeneous_controls already projects only finite endpoints and retains zero or mixed intermediate weights exactly.

Preferred direction after the unit projection candidate: make conic subdivision return the existing common BezierSubcurve2 carrier (with uncertainty propagated consistently), selecting the native conic only when the three affine controls exist and otherwise retaining the general homogeneous quadratic. Update callers directly, including CurveGeometry2::from_bezier, retained overlap and the specialized tests/benches; do not add a compatibility method. The exact return classification and controlled caller inventory still need implementation review.

Reduce machinery at the same boundary: remove the duplicate private HomogeneousControl and its vector-of-vector de Casteljau helper in favor of HomogeneousControl2 and the existing homogeneous interpolation primitives. A quadratic blossom can construct a restricted control net directly from both bounds, avoiding nested subdivision and an unnecessary start/end division. Preserve the ordinary positive-weight native path and measure its cost rather than forcing every conic through a heavier carrier.

Required evidence: carry the implicit conic, supporting circle/tangent certificates and parameter lineage to either result. A failed affine-control projection is not a failed geometric endpoint. Endpoint poles must remain excluded; zero or uncertified intermediate weights do not require division. Keep exterior-domain behavior explicit and never reuse a unit weight-sign proof outside its domain. Include the existing area, negative projective scale, conic provenance, circle tangency, exterior-pole, and split-of-split guards along with both public policies and reversed traversal.

This note proposes no code already applied. V644 is the only active build/qualification, and its frozen inputs are unchanged.
