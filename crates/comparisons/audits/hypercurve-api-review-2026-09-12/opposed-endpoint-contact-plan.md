# Shared finite line endpoints before a zero determinant

Downstream CSGrs qualification exposed an additional exact-decision gap after normalized admission: `cycloidal_rack_alternates_face_and_root_flanks` returned an empty region because its convenience wrapper discarded a construction blocker. The archived Hypercurve parent `8977b81` admits the raw rack but fails explicit STRICT regularization with the same `RealSign` blocker. Commit `9f7a636` correctly exposes that unresolved decision at admission. This is required closure work, not an exclusion.

The immutable public fixture `normalized-admission-cycloidal-rack.rs` copies the authored exact rack points and records both policies for one and four teeth. A second public fixture enumerates every segment pair for one tooth, both as native lines and exact degree-elevated quadratics. Exactly two adjacent pairs fail: indices 10/11 and 27/28. They meet at the pitch line, with opposing outgoing directions. Canonicalizing the analytically known cycloid endpoints alone does not repair the gap; that rejected experiment is archived separately and is not a production change.

The primitive line solver currently asks whether the two supporting directions have a zero cross product before publishing their shared endpoint. That equality is unnecessary. Distinct lines have only the shared point. Coincident lines whose outgoing endpoint rays have a strictly negative dot product also have only the shared point. A negative dot product therefore proves singleton intersection without selecting either cross-product branch.

The implementation adds this exact certificate before support classification. Endpoint identity is retained directly; the dot sign is requested under STRICT regardless of the surrounding policy. Unproved cases fall through to the existing solver. Same-direction overlap and acute endpoint cases retain their previous classification. Preview-tolerance behavior is left to its existing path. No new public API or compatibility wrapper is added.

The regression exercises both policies, both operand orders and every endpoint orientation. It passes against the actual candidate libtest. The unchanged public fixture now admits and regularizes both racks with `Certified` STRICT results, and all segment pairs pass in both representations. APPROXIMATE_512 admission still records a consumed terminal elsewhere in the arrangement; this change does not claim to eliminate every optional approximate decision.
