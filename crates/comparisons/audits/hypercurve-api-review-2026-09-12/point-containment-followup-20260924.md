BezierParallel2::contains_point_evidence has an additional incident-domain
argument and is therefore not simply the same overload as its finite-range
contains_point method. Its current dispatch declines some retained circle and
derived-point variants. A complete general incidence query must reuse their
selected field in the parallel fiber equations, preserving the positive-speed
sheet, finite/incident domain ownership and local root identity. Routing every
variant through independently projected Cartesian coordinates would lose the
correlation and repeat the machinery this migration is intended to remove.

The general parallel follow-up remains unimplemented.

For the remaining general-point/parallel query, the geometric equations on a
certified regular source cell are small. With D=Q-P(t), T=P'(t), and signed
offset d, require D dot T=0, D dot D=d^2, and, for nonzero d, sign(T cross D)
=sign(d). The last condition retains the intended normal sheet after squaring.
For d=0, direct coordinate incidence avoids imposing source regularity merely
to recognize an authored source point. Source poles and one-sided stationary
endpoint tangents still belong to the existing domain/regularity authority.
The query point's shared homogeneous field can supply these coefficient rows;
the selected source root should remain over that field. Identically vanishing
rows require the existing whole-component result rather than an arbitrary
sample point or empty list. This is a proposed reuse of the retained fiber
solver, not a claim that the remaining query families are implemented.
