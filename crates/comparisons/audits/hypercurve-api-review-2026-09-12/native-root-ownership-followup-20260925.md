# Preserve imported singleton endpoint ownership before caching witnesses

Static audit during V63 ray/chord qualification found a separate native adapter issue. Hypersolve intervals with positive width own `(lower, upper]`. `BezierParameter2::from_algebraic_root_representation_unbounded` imports them without changing those bounds, but native `same_value` accepts both endpoints and `disjoint_parameter_interval_order` treats either touching endpoint as strict separation.

Counterexample to dynamically verify next: import F(t)=t(t-1) on (0,1], distinct_root_count=1, exact_root=None, with valid upstream evidence. The selected root is 1. The current native Exact/Algebraic `same_value` branch accepts Exact(0), because it allows equality to the lower bound and F(0)=0. The current interval comparator reports the imported root Less than Exact(1), because its upper bound touches that point. Both outcomes contradict the imported certificate. No executable regression has been run for this audit yet.

Prefer preserving half-open ownership across the native adapter, not eager reconstruction or mandatory refinement at every import. Positive-width native intervals may use the same ownership convention; public constructors already exclude endpoint roots, so their meaning does not change. A touching boundary certifies left < right only when the right interval excludes its lower endpoint, and symmetrically for left > right. Exact/Algebraic equality must reject an excluded lower root but retain an owned upper root. Audit all other endpoint-order shortcuts, native refinement, projective orientation transport, and shared-root identity before changing the invariant. Add imported-root regressions for repeated factors, interior roots with a foreign lower-endpoint root, owned upper roots, exact point intervals, conjugates, and both policies.

This must precede the scalar-witness cache proposal in `native-root-witness-followup-20260925.md`: otherwise an invalid native equality could become a persistent exact scalar witness. The ray/chord V63 candidate does not change this adapter or rely on newly cached equalities.

Do not mechanically declare every transformed interval `(lower,upper]`: a decreasing affine/projective map sends an owned upper-endpoint root to an owned lower endpoint. Either preserve that ownership explicitly or establish and retain the mapped scalar witness before discarding it. Test reversal, unit complement, decreasing affine maps and projective maps of imported certificates, including an owned endpoint with no prepopulated exact_root hint. The existing native comments promise non-root endpoints, so the adapter and all transformations must share one explicit invariant rather than mix conventions.

That theorem excludes endpoint roots; it does not prove that the norm has no endpoint roots. A norm may retain a conjugate-sheet root at a bound while its one selected root is strictly inside. Normalize that open-interval carrier by removing certified factors at both excluded endpoints, preferably sharing the import's exact deflation helper.
