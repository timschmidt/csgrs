# Biquadratic scalar bases in the existing quadratic tower

Production candidate: Hyperreal only, two files. Qualification and commit status are recorded separately; the full Hypercurve goal remains incomplete.

The reversed selected-rational chamfer reaches Hypersolve's exact subresultant determinant. Its intermediate coefficient has no selected variable: the blocker is an ordinary Real zero decision. Deferring intermediate coefficient decisions in a diagnostic Hypersolve build moved the same unresolved scalar to the final topology proof and hit 120 seconds. That experiment is rejected; Hypersolve production is unchanged.

One exact scalar was serialized as a bounded replay artifact (522,408 bytes; SHA-256 `70bb4440470b5b09b09ba1f472a48bcb5bb4fa79ed60af6cd77c97133a4f3991`). It contains only rational arithmetic, sqrt(3), sqrt(7), negation and binary scaling. Its 14,628 serialized node occurrences reduce to 365 distinct expression shapes. Independent Fraction arithmetic in the basis 1, sqrt(3), sqrt(7), sqrt(21) gives four exactly zero coefficients; the largest intermediate rational coefficient needs 28 bits. No floating-point conversion is evidence for that equality.

The committed Hyperreal parent declines even the positive sum sqrt(3)+sqrt(7) through `quadratic_tower_sign`. It also declines the sharing-preserving replay of the captured zero. Their standalone executable/source/library bindings are archived. Raw serialization loses DAG sharing, so its standalone timing and node count are diagnostic only; the generated replay gives each distinct expression one local binding.

Hyperreal's existing `Tower` already represents Q(sqrt(d))(sqrt(a+b sqrt(d))). Biquadratic fields are a subset of that representation. The candidate aligns differently presented biquadratic operands instead of introducing another scalar type or a geometry-specific exception. It expands an unnested tower into at most three quadratic terms, selects two rational square classes, and admits another term only when sqrt(c/outer) lies in the chosen inner quadratic field. Then sqrt(c)=sqrt(c/outer)*sqrt(outer), using principal positive roots. Signed rational multipliers remain signed. A third independent class declines.

Native tower multiplication remains first, followed by common biquadratic-basis multiplication, then the earlier squared-radical product rule. That ordering is essential: the earlier rule can represent a mixed quadratic value times another root by squaring the value and introducing a nested square root. Although exact, that representation obscures the existing four-dimensional field and prevents later reuse. Genuinely nested outer radicals retain their existing path. Exact signs, norm-based inverses, rational bit bounds and the node budget remain authoritative. This adds no public API and does not enlarge the scalar representation.

The new public scalar regression uses three independent radical pairs, both operand orders, square expansion, all four field basis terms, inverse cancellation, positive/negative perturbations and rejection of a third independent radical. The Hypercurve regression sweep exposed a test whose fixture was mathematically valid but expected InvalidEvidence because older strict arithmetic could not order its close nonrational endpoints. The interval is [sqrt(1/2-epsilon), sqrt(1/2+epsilon)] for epsilon=2^-1200, so it contains exactly one positive root of x^2-1/2. The candidate correctly computes its negated representation. The sweep completed 1,205 cases: 1,198 passed, six ignored, and this test expectation failed. No other previous pass regressed.

The first negative test migration supplied an empty interval but retained a false distinct-root-count claim. It was accepted. Inspection showed that this is the documented structural-validation contract, not a regression: `validate_algebraic_root_representation` explicitly relies on upstream isolation for uniqueness, and `replay_rational_arithmetic_input` does the same. An initial commentary diagnosis calling this a new correctness defect was corrected. This probe is not evidence that Hyperreal's scalar decisions were wrong. The final test instead preserves the valid enclosure and rejects reversed bounds and an explicitly false point witness, the invariants this adapter actually replays. The invalid cases still carry the stale Valid label and unit-root count, and both policies must report Certified rejection.

Architectural debt remains: the represented-root payload and its root-count/validation fields are public and independently forgeable. A later certificate API migration should make uniqueness evidence a retained authority issued by isolation, with private validated payloads and controlled constructors, instead of treating a public count as a proof or rerunning Sturm on every use. Callers must migrate directly, without a compatibility wrapper. The full goal cannot claim evidentiary closure for this boundary merely from structural validation.
