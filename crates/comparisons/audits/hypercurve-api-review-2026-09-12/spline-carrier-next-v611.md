# Spline API consolidation audit (not implemented)

Follow demonstrated closure repairs, including V600, before this optional API simplification. V605 qualification is active and no production files were changed for this audit.

The inventory in spline-carrier-uses-v610.json scans all 2047 production-manifest sources. PolynomialBSplineCurve2 has25 references in6files; RationalBSplineCurve2 has43 in6. Their only external-to-module users are the retained cache owners, lib.rs exports, benches/bspline.rs, fuzz/fuzz_targets/bspline.rs and tests/hypercurve_bspline.rs. No downstream production crate uses either lower-level authoring carrier. The retained PolynomialSplineCurve2 has56 references in17files (csgrs consumer); NurbsCurve2 has129 in23files (hyperbrep persistence consumer).

Potential consolidation: one public polynomial spline and one public NURBS authoring value, with private homogeneous/extraction machinery. No alias or forwarding compatibility interface. Update the three owned benchmark/fuzz/test callers to the retained APIs. Avoid merely hiding types and adding duplicate queries: NurbsBezierDecomposition2 currently wraps RationalBSplineBezierExtraction2 with no other state and forwards five queries, so those representations can be one actual result type. PolynomialSplineBezierDecomposition2 adds source knot intervals, which should stay beside the extracted spans rather than be reconstructed by each consumer. The current independently exposed extraction also provides span_fact_evidence and native_subcurves; migrate that real evidence capability rather than removing coverage or replacing it with approximation.

Admission needs explicit review: lower carriers validate algebraic control/knot data; retained curves additionally obtain finite endpoints and periodic seam certificates. Preserve rejection vs uncertainty semantics and exact mixed/zero homogeneous weights. Tests of purely algebraic definitions whose active endpoint is a pole may belong with private extraction internals rather than a public finite curve. Do not change a test merely to fit the new constructor. Benchmark cold extraction separately from clone-shared cached decomposition so replacing calls does not silently change the measured workload. Fuzzing should retain independent knot-insertion/extraction facts, signed/zero weights and both original and refined descriptions.

Later machinery reduction can place the authoring control net directly on the cache owner and share one rational span grammar, while retaining the polynomial low-degree fast paths and arbitrary positive degree. This remains an audit, not an applied migration or a claim of spline closure defects.
