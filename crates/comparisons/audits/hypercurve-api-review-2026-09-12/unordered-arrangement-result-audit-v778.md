The unordered-segment result is a removable reporting layer.

Successful geometry is already one normalized CurveRegion2. The report stores an optional region, duplicated source/fill inputs, stage/status/blocker combinations, ring/span counts and optional native kind counts. The raw adapter eagerly computes a native lowering solely to populate kind counts; no later construction decision consumes this summary. The helper region_segment_kind_counts is used only here. RetainedTopologyStatus is used by other modules, so retain that public type outside this adapter.

Proposed direct API: ExactCurveResult<CurveOutcome<CurveRegion2>>. Endpoint assembly uncertainty becomes ExactCurveError::Blocked for Construction; existing path/arrangement errors retain their original family and reason. Keep the ring assembly, per-walk fill/global parity semantics and regularization algorithm. Return the existing region directly. Remove the result and stage types, blocked-result factory, summary-count kernel and eager native lowering. Callers request boundary_loops or structural_facts only if needed; examples,benchmarks and tests migrate directly. Do not introduce aliases or report compatibility adapters.
